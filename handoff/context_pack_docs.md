# Objectives

What this project is for, what "done" means for each part, and what is
deliberately out of scope. The history at the end records how the
objectives grew, so a new contributor can tell requirements from
experiments.

## 1. The RAG engine

**Goal:** a header-only C++20 retrieval-augmented generation (RAG) engine
written the way low-latency trading systems are written: predictable tail
latency, no allocation on the hot path, explicit memory layout, and
measured rather than assumed performance.

Functional requirements:

* Ingest documents (plain text, source files, PDFs with page numbers),
  chunk them with overlap, embed and index them.
* Hybrid retrieval: dense vector search plus BM25, fused by reciprocal rank
  fusion, with four dense modes (exact, int8 + rerank, IVF, IVF-SQ8).
* Build a prompt into a fixed buffer, with citations (`[n] (source, p. X)`),
  ready for any LLM (the generator itself is a concept, not a dependency).
* Persist an index to disk and load it back, safely.

Non-functional requirements and how they're enforced:

| Requirement | Target | Enforced by |
|---|---|---|
| No heap allocation on the query path | 0 allocations per query | global `operator new` counter in tests (R2) |
| Concurrency | queries concurrent with ingest and commit | TSan job, `rag_stress` (R7) |
| Batched queries | bit-identical to single queries | tests (R6) |
| Crash safety | saves survive power loss; forged files are rejected | fsync + rename + directory fsync (R10); structural validation and forgery tests (R9) |
| Robustness | no UB or memory errors on any input | ASan/UBSan (GCC and Clang), libFuzzer harnesses |
| Latency | sub-millisecond p99 at 60k chunks | IVF-SQ8: p99 0.43 ms (R5; README) |

## 2. The self-learning agent

**Goal:** a self-learning agent whose architecture can be studied piece
by piece (environment, encoder, learners, exploration, supervision), on
tasks where the optimum is known exactly, so every claim is a measurement.

Objectives, in the order they were added:

1. Learn optimal execution (sell 100 lots in 20 steps with a predictive
   signal and market impact) from rewards alone, scored against an exact
   DP optimum.
2. Supervise learning the way production systems need: held-out
   evaluation, champion/challenger deployment, drift detection and
   re-exploration, a policy bank for returning regimes, and a guard against
   deploying anything worse than a simple baseline.
3. Compare learning paradigms on the same task: tile-coded Q-learning,
   episodic memory, actor-critic, and a model-based agent that learns the
   market and plans, including what happens when the model is wrong and how
   to detect it.
4. Show the architecture is task-agnostic: a second task (market making)
   on which the unchanged agent finds the optimal policy.
5. Measure the things means hide: online cost of learning, tail risk,
   off-policy evaluation from logs.

What "success" means for the agent: each experiment answers a stated
question with numbers, across seeds, against the exact optimum, and records
the result even when it's negative (EXPERIMENTS.md). Library defaults
change only when an experiment shows they should (DECISIONS.md).

## 3. The hand-off pack

**Goal:** another AI, or a person, can take over the project from these
documents alone.

* `llms.txt` and `docs/ai/` describe everything; `tools/make_context_pack.py`
  bundles them into one file (optionally with every source file).
* Every API snippet in API.md compiles and runs as a test.
* The pack is kept current after every experiment and pushed with it.

## Non-goals

* A neural embedding model or an LLM client. Both are concepts
  (`Embedder`, `Generator`) so they can be plugged in; none could be
  downloaded and tested in this environment.
* Distributed or multi-node operation; deletes and updates of indexed
  chunks (STATUS.md lists these as limitations).
* A realistic market simulator. Both trading environments are stylized on
  purpose: they keep an exact optimum computable, which is what makes the
  agent's numbers meaningful. Real market data would make the price-impact
  model an untestable assumption.
* GPU support.

# Project map

rag-cpp is a header-only C++20 library with two parts:

1. **A RAG engine** (`include/rag/`): hybrid retrieval (dense vectors + BM25,
   fused by reciprocal rank fusion) with a zero-allocation query path, SIMD
   kernels, lock-free concurrent ingestion and commits, persistence, and PDF
   ingestion with page citations.
2. **A self-learning agent** (`include/rag/agent/`): reinforcement learning
   with held-out evaluation, champion/challenger deployment and drift
   detection. It is demonstrated on an optimal-execution task whose exact
   optimum is computed by dynamic programming.

### No RL library

The reinforcement-learning stack is written from scratch in
`include/rag/agent/`; no Gymnasium, Stable-Baselines3, RLlib, PyTorch or
other framework is used. What each piece corresponds to:

| Piece | Header | Closest off-the-shelf equivalent |
|---|---|---|
| `Environment` concept (`reset`, `step`, `features`, action count, feature ranges) | `env.hpp` | Gymnasium `Env` |
| Tile coding, random Fourier features | `features.hpp` | Sutton's tile coder; scikit-learn `RBFSampler` |
| Q-learning (n-step, replay, annealed step size), episodic k-NN memory | `learners.hpp`, `agent.hpp` | SB3 DQN (with a linear model instead of a network) |
| Neural Q-learner: MLP, backprop, Adam, target network (`NeuralQ`) | `mlp.hpp`, `agent.hpp` | SB3 DQN / PyTorch |
| Actor-critic (softmax policy, TD critic) | `agent.hpp` | SB3 A2C |
| Model-based agent (regression + DP planning) | `model_based.hpp` | none standard |
| Exact optima by dynamic programming | `execution_dp.hpp`, `market_making.hpp` | none (task-specific) |
| Training loop, held-out evaluation, champion, drift detection, policy bank, baseline guard | `trainer.hpp`, `drift.hpp` | partly RLlib / SB3 callbacks |
| Paired evaluation, CVaR | `evaluate.hpp` | none standard |
| Off-policy evaluation (PDIS, WPDIS, DR, ESS) | `ope.hpp` | SCOPE-RL, d3rlpy OPE |

Why from scratch:
* **Latency:** a greedy decision costs 64 ns (TileQ) with zero heap
  allocations, which a Python framework can't approach.
* **Transparency:** each update rule is a few lines (TASK_SPECS.md §5),
  which matters because the agent is meant for learning the architecture.
* **Reproducibility:** every random draw comes from seeded generators, so
  experiments reproduce bit for bit, and paired comparisons (common random
  numbers) are exact.
* **Exact yardsticks:** the tasks are built so a DP can compute the optimum;
  that integration is simplest when everything shares one codebase.

The trade-off: the neural network is small and CPU-only (an MLP in double
precision, no GPU, no automatic differentiation beyond the hand-written
backpropagation), and there are no vectorized environments or distributed
training. E16 tested whether a framework-style neural learner would help:
the from-scratch MLP did (84–89% vs 65–69% on execution).

## Numeric conventions

* Embeddings: `float` (fp32), L2-normalized; int8 copies with one scale per
  row.
* Agent: `double` throughout; actions are `std::uint32_t`.
* Randomness: xoshiro256** seeded through splitmix64 (`rng.hpp`);
  normal variates by the Marsaglia polar method. Every experiment is
  deterministic given its seeds; evaluation episode i always uses
  `Rng(seed + i)`.
* Floating point: results are bit-reproducible on one build. Across ISAs
  and compilers, FMA contraction can change the last bits, so tests assert
  tolerances or directions, not exact learned decisions.

## 1. Index and query

# RAG engine internals

The engine is `rag::RagEngine<Embedder E, std::size_t MaxK = 64>` in
`include/rag/engine.hpp`. Read this before changing anything in `include/rag/`.

## Data flow

```
INGEST (one writer thread)
  text ─► Arena copy ─► tokenize (Token{offset,len,hash}) ─► chunk_tokens (window/overlap)
       ─► per chunk: Embedder::embed ─► VectorStore::append (fp32 + int8 + scale)
                     Bm25Builder::add (term hashes, stopwords removed)
                     ChunkMeta {text, len, doc_id, ordinal, page_first, page_last, source}
  commit() ─► new Snapshot{Bm25Index frozen, IvfIndex (if an IVF mode)} ─► atomic exchange ─► EBR retire old

QUERY (any number of threads, each with its own QueryContext; zero heap allocations)
  prepare:  tokenize ─► terms (no stopwords) ─► embed ─► has_signal = |qvec|² > 0
  pin snapshot (EpochDomain::Guard), live = store.size() (acquire)
  dense:    Exact      flat fp32 scan of [0, live)
            Int8Rerank int8 scan -> shortlist (rerank_candidates) -> fp32 rerank
            Ivf        IVF over [0, covered) + exact scan of the delta [covered, live)
            IvfInt8    IVF-SQ8 shortlist -> fp32 rerank + exact delta scan
            (admission floor: score > dense_min_score, default 0)
  lexical:  Bm25Index::search over the snapshot (impact sums into a dense accumulator)
  fuse:     RRF(k0 = 60) over the dense and lexical lists
  prompt:   build_prompt into ctx.prompt_buf with citations "[n] (source, p. X)"
```

## Key data structures

| Structure | Layout | Why |
|---|---|---|
| `VectorStore<D>` | separate aligned arrays: fp32 rows, int8 rows, per-row scale; `size_` on its own cache line | scans stream contiguous memory; readers never false-share with the writer |
| `TopK<Cap>` | `std::array` heap + cached threshold + `sorted_` flag | reject path is one compare; NaN rejected; deterministic ties (score desc, id asc) |
| `Bm25Index` | open-addressing term table (power of two, load ≤ 0.5) + SoA postings (doc u32, weight f32) | query = gather-add of precomputed impacts |
| `IvfIndex<D>` | centroids + CSR `offsets/ids` + contiguous reordered rows (fp32 and/or int8) | probing a list is a sequential read |
| `Arena` | list of blocks that never move | `string_view`s into it stay valid for readers |
| `EpochDomain` | 128 reader slots of 64 B each (active epoch, in_use, depth) | per-reader pinning with no shared writes |

## Concurrency contract (enforced by TSan tests and `rag_stress`)

* `ingest()` and `commit()` run on **one writer thread at a time**.
* `query()` / `query_batch()` run on any number of threads, **concurrently
  with ingest and commit**. Each thread owns a `QueryContext`; at most 128
  can be live.
* **Publication:** the writer fills a row and its `ChunkMeta`, then does
  `size_.store(n+1, release)`. Readers do `size()` (acquire) and see only
  complete rows.
* **Snapshots:** `commit()` builds a new `Snapshot` off to the side, publishes
  it with `snap_.exchange(seq_cst)`, retires the old one with the current
  epoch, and frees it once no reader slot holds an older epoch
  (`EpochDomain::quiescent_since`).
* **Lifetime:** destroy every `QueryContext` before the engine.

## Validation added by the property-test review (R13–R17)

* `EngineConfig`: BM25 `k1` must be finite and ≥ 0, `b` in [0, 1].
* `Bm25Index::load()`: every posting weight must be finite and > 0.
* IVF list rows are scored with `simd::dot1` (bit-identical to the exact scan).
* IVF training uses at least one point per list; `build(store, 0)` resets.
* `tests/rag_property_tests.cpp` checks these and the properties above on

## Invariants that tests rely on (don't break these)

1. **Bit-exact batching:** `query_batch` returns bit-identical results to
   `query`. This holds because `simd::dot1` matches one lane of `simd::dot4`
   exactly, and the exact scan uses `dot1` for tail rows. Use `dot1`, not
   `dot`, wherever a score must match a `dot4` lane.
2. **Zero allocation:** the query path makes no heap allocations. A global
   `operator new` counter in `rag_tests.cpp` enforces it.
3. **Scratch reset:** `Bm25Scratch::acc` is all zeros between queries.
4. **Ordering:** `TopK` orders by score descending, then id ascending.
5. **Validate before mutating:** `ingest()` checks `IngestOptions` before
   touching anything. Invalid page offsets throw and leave the engine
   unchanged.
6. **Safe loading:** loading never trusts a field. Every offset, length and
   id is checked against the structure it indexes, and `tests/forgery_tests.cpp`
   covers each check with a valid-checksum forged file. Add a forgery case
   for every new field.

# A self-learning agent, piece by piece

`include/rag/agent/` holds a complete self-learning agent in about 2,400 lines
of header-only C++20. Its task: sell 100 lots over 20 steps without being told
how the market works. It learns from rewards alone and gets within reach of
the mathematically optimal strategy. It also notices when the market changes
and relearns.

```bash
./build/agent_demo   # the whole story in about 5 seconds
```

This document explains the architecture. Every number quoted here comes from
`agent_demo`, the tests in `tests/agent_tests.cpp`, or the benchmarks.

---

## 1. The loop

Every self-learning agent, whether a robot, a game player or an LLM agent
with memory, is some version of this loop:

```
                  ┌──────────────────────── Trainer (supervision) ────────────────────────┐
                  │  held-out evaluation · champion/challenger · drift detection           │
                  └───────▲───────────────────────────────┬────────────────────────────────┘
                          │ scores, alarms                 │ reexplore(), forget_experience()
                          │                                ▼
 ┌─────────────┐  obs   ┌─────────┐ features ┌──────────┐ Q-values ┌──────────┐ action ┌─────────────┐
 │ Environment ├───────►│ Encoder ├─────────►│ Learner  ├─────────►│  Policy  ├───────►│ Environment │
 └──────┬──────┘        └─────────┘          └────▲─────┘          │ ε-greedy │        └──────┬──────┘
        │                                         │ update         └──────────┘               │
        │                                   ┌─────┴──────┐                                    │
        └────────── reward, next obs ──────►│   Memory   │◄───────────────────────────────────┘
                                            │ replay /   │
                                            │ episodic   │
                                            └────────────┘
```

| Stage | Question it answers | Here | File |
|---|---|---|---|
| Environment | What is the world, and what counts as good? | `ExecutionEnv`, `ChainEnv` | `env.hpp` |
| Encoder | How should situations be described so that similar ones are treated alike? | tile coding, random Fourier features | `features.hpp` |
| Learner | What is each action worth here? | `TileQ` (TD learning), `EpisodicMemory` (k-NN) | `learners.hpp` |
| Memory | What happened before? | `ReplayBuffer`, episodic slots | `learners.hpp` |
| Policy | What should I do now, and when should I try something new? | ε-greedy with schedules | `agent.hpp` |
| Supervision | Am I actually improving? Has the world changed? | `Trainer`, `DriftDetector` | `trainer.hpp` |
| Yardstick | How good could I possibly be? | `ExecutionDP` | `execution_dp.hpp` |

The agent (`Agent<Env>`) is generic. It sees only observations, an action
count, rewards, and the feature ranges an environment declares. The same
class learns the corridor (`ChainEnv`) and the trading task unchanged.

---

## 2. The task, and why it needs learning

`ExecutionEnv`: sell `lots = 100` over `horizon = 20` steps.

* **Impact:** selling `q` lots in one step costs `0.01·q²`. Fast selling is
  expensive, and the cheapest schedule ignoring everything else is TWAP
  (5 lots per step).
* **Signal:** the price moves by `alpha·signal + noise` after each step. The
  signal persists (AR(1), ρ = 0.7), so a negative signal means the price is
  about to fall and it pays to sell now.
* **Deadline:** anything unsold at the end is dumped at 5× the impact.
* **Reward:** the change in mark-to-market wealth. An episode's total reward
  is exactly cash received minus the arrival value. A test checks this to
  1e-9 for random policies.

The agent is never told the impact, the deadline rule, or what the signal
means. The demo's opening table gives the scale:

| Policy | Gain over TWAP per episode |
|---|---|
| TWAP | 0 |
| rule: "sell faster if signal < 0" | +6.5 (43% of optimal) |
| **DP optimum** (knows the model) | **+15.2** |
| learned agent after 40,000 episodes | **+10.1 (67% of optimal)** |

## 3. The yardstick: know what optimal looks like

`ExecutionDP` solves the task exactly (backward induction over time,
inventory and a 121-point signal grid, in 17 ms; 3.4 ms on the 61-point grid
the model-based agent replans with). The expectation over the next signal is
the same linear map of a value row for every time step, inventory and
action, so it's precomputed once as a banded matrix: each (time, remaining
inventory) costs one banded product, and each action then costs O(1). That
made the solve ~9× faster with identical decisions.

This matters for any learning system. "The reward went up" is weak evidence.
"It captures 67% of the gain the optimal policy achieves on the same unseen
scenarios" is a measurement. Before trusting the DP, the tests check:

* its predicted value matches simulation (paired gain 15.59 vs 15.61);
* it beats every heuristic;
* its last-step choices match a brute-force calculation;
* it is mirror-symmetric (flipping `alpha` and the signal together leaves
  the value unchanged).

**Evaluation method.** Single-episode returns have a standard deviation
around 55, far larger than the differences between policies, so comparisons
use *common random numbers*. Every policy faces the same scenarios
(`Rng(seed + i)`), and paired differences cancel the shared noise (see
`compare()` in `trainer.hpp`).

**Tails, not just means (E14).** Scored on cash outcomes, the risk-neutral
optimum is more volatile than TWAP (sd 57 vs 54) yet its worst 5% of days
average −66 against TWAP's −117: the signal lets it avoid the worst
outcomes. `episode_returns()` and `cvar()` in `evaluate.hpp` measure this.

**Risk aversion.** With `ExecutionParams::risk_aversion` λ > 0, each step's
reward also subtracts λ·σ²·I², the price variance the held inventory adds.
The DP stays exact for this mean-variance objective, and it shows the classic
trade-off: as λ goes from 0 to 1, the optimum sells 26 → 73 lots in its
first 5 steps, the sd of its cash falls 59 → 28, and its mean falls
+9.3 → −8.4 (E4). The tail barely improves, though: the worst 5% goes from
−66 to −61 (E14). On market making the same kind of penalty does lift the
tail (worst 5%: −5.7 → +13.7 for 7% of the mean), because there the tail is
inventory.

## 4. Encoders: deciding what "similar" means

Learning generalizes only through the encoder. Two are provided:

* **Tile coding** (for `TileQ`). There are 8 offset grids over
  (time, inventory, signal), and a state activates one cell in each. Nearby
  states share most cells, so learning in one transfers to its neighbours.
  Tests check that shared cells fall with distance, from all 8 for the same
  point to 0 for distant ones.
* **Random Fourier features** (for episodic memory). A 64-dimensional unit
  vector whose dot products approximate a Gaussian similarity
  (Rahimi & Recht). "Recall similar past situations" then becomes exactly
  the nearest-neighbour search the RAG engine runs over text embeddings, and
  it uses the same SIMD kernels (`simd::dot4`) and top-K selection.

*Lesson measured:* finer tiles made learning worse. With 12 cells per
dimension the agent captured 40% instead of 65%, and with one cell per time
step, 15% at 30,000 episodes. Each cell sees fewer samples, and neighbouring
states stop sharing what they learn. Generalization was worth more than
resolution.

## 5. Two ways to learn

| | `TileQ` (parametric) | `EpisodicMemory` (instance-based) |
|---|---|---|
| Stores | one weight per tile per action | up to 4,096 remembered situations, each with a value per action |
| Learns from | every step (3-step TD target `r + r' + r'' + max Q(s''')`) plus replay | each episode's actual returns (Monte Carlo) |
| Estimates Q by | summing 8 weights | similarity-weighted mean of the 8 nearest memories |
| Decision cost | **64 ns** | 19.8 µs (k-NN over 4,096 × 64 floats) |
| After 1,000 episodes | 5.8% of optimal | **13.6%** |
| After 40,000 episodes | **62-71%** (across seeds) | ~33% at 10,000 and improving slowly |

Episodic memory turns one good episode into a usable memory immediately.
The parametric learner generalizes smoothly and wins with data. This is the
"complementary learning systems" idea from neuroscience, and the reason some
agents combine both.

**Replay** (`ReplayBuffer`): every real step adds 4 extra updates from past
transitions, so each interaction with the world is used many times.

**Step size** (`alpha / (1 + episodes/3000)`, floor 0.003): rewards here
are noisy (about ±2.5 per step), while the difference between good and bad
actions is often below 1. A constant step size keeps estimates jittering,
and shrinking it averages the noise out. The floor keeps the agent able to
learn if the world changes.

*Lessons measured:*
* **Plateau:** with 1-step targets, learning levels off around 72%; with the
  default 3-step targets, 75–77% at 200,000 episodes. It is *not* the
  representation's limit. The same tiles fitted to the true optimal values
  give 99.5%. The gap is target noise: returns vary by ±20–50 while action
  values differ by less than 1. See `docs/ai/EXPERIMENTS.md` E2.
* **Model-based alternative:** an agent that learns the market's 5
  parameters and plans with the DP reaches 99–100% in 20–50 episodes
  (`model_based.hpp`, E1), as long as its assumed model form is right.
  See "When the model is wrong" below for what happens when it isn't.
* **Actor-critic (`LearnerKind::ActorCritic`) is the best model-free
  learner here.** It learns a softmax policy directly, with a tile-coded
  critic V(s) whose TD error is the advantage: 75–78% at 10,000 episodes,
  80–86% at 40,000 and 86–89% at 200,000. Its failure mode is different:
  too small an actor step, or annealing too early (`ac_decay_episodes`
  3,000), leaves the policy near-uniform, which loses money (E5).
* **A neural network breaks the plateau (E16).** `LearnerKind::NeuralQ`
  replaces the tiles with a small MLP (two hidden layers of 64, written
  from scratch in `mlp.hpp`: no ML library), trained DQN-style on the same
  3-step targets: 84–89% at 40,000 episodes against 65–69% for TileQ.
  Ablations rule out the target network and Adam; giving TileQ 32 replayed
  updates per step made it worse. The difference is how the function
  generalizes: coarser tiles, which average the noisy targets over more
  states, already reach 76–77%, and the network goes further. The cost:
  ~75× the training compute and 1.7 µs per decision instead of 39 ns.
  With Double DQN targets it is the best model-free learner on the
  E21 leaderboard: 91.5% [90.1, 92.7] at 40,000 episodes over 8 seeds,
  against 81.9% for actor-critic and 66.7% for default TileQ.
* **Double Q-learning didn't help.** It removes the upward bias that
  `max()` puts into targets. Here, though, the two were level at 30,000
  episodes (64.8% with it, 64.5% without), and at 60,000 it was clearly worse
  (64% vs 72%): halving each estimator's updates cost more than the bias it
  removed. It's available as `double_q` but off by default.

### When the model is wrong
Add a market feature the model has no term for (permanent impact: every lot
sold lowers the price of everything still held) and the ranking flips. The
model-based agent falls to 22–55%, while TileQ and actor-critic stay at
70–91%, because they assumed nothing. Worse, the wrong model degrades *with*
data (43% → 25% from 20 to 300 episodes): its plan exploits the model's
error, so the data it collects grows more one-sided. Three tools address
this (`docs/ai/EXPERIMENTS.md` E7):

1. **Check the model** (`check_model()`): the gain over TWAP the model
   predicts for its plan (exact, by `ExecutionDP::policy_value`) against the
   gain measured on real scenarios, paired. A wrong model is always
   optimistic, because the planner picks the actions its errors flatter.
   After 100 episodes a correct model scores |z| ≤ 2.5 and a model missing a
   term scores z ≥ 8.5.
2. **Expand the model class** when the missing term is known
   (`learn_permanent_impact`): back to 99.9%, at a cost of ≤ 0.3 points
   where the term isn't needed.
3. **Warm start + guard** when it isn't known: `Agent::distill()` copies
   the model's Q-values into the tiles (in the model's own simulator, so no
   real episodes are spent), RL fine-tunes them on real rewards, and
   `set_baseline(plan)` keeps the plan deployed until the learner beats it.
   Fine-tuning alone wrecks a correct model's 99% policy (to 35–57%): TD
   noise (≈ √(α/2)·σ ≈ 2) is larger than the action gaps (< 1). With the
   guard, the result is 100% when the model is right, and 78–82% (never
   below the plan) when it's wrong.

### When the world changes, for a model
A model that never forgets averages the old and new worlds: 20 episodes
after the signal flips it's at −166% of the new optimum, and still −123%
after 100. Constant forgetting tracks the change but always plans on little
data (54–93% in a noisy, stable market). The model-based agent therefore
uses the same idea as the trainer: a CUSUM test on surprise (episode return
minus what its plan predicted), and on an alarm it starts its statistics
over. It recovers to 95–100% within 20 episodes, against 5,000 episodes
for the model-free agent to reach 18%, and costs nothing while the market
is stable (E9).

### Scoring a policy before deploying it
The trainer's held-out evaluations and the paired model check replay
scenarios, which needs a simulator. From live logs alone, importance
sampling reweights the logged episodes by how likely the target was to act
as the behaviour did. At a horizon of 20 that fails: a target that differs
from the logged policy in many states is followed by almost no logged
episode beyond a few steps, so the effective sample size collapses to ~0
and errors are 45–2,968% of the optimal gain even with 10,000 logs.
Evaluating the target under a fitted model works (2–4%) when the model
class is right; doubly robust estimation only repairs model bias for
targets close to the logged policy (`ope.hpp`, E10). Offline evaluation
therefore comes back to the same requirement as model-based control:
check the model.

## 6. Exploration

A fraction ε of decisions is random. ε falls linearly from 1 to 0.02, and
never reaches 0: an agent that never tries anything new can never notice that
the world changed. `reexplore(eps, n)` raises it temporarily and restarts
the step-size schedule, because relearning needs plasticity. Greedy decisions
(`act(o, false)`) are deterministic and don't touch the agent's random
number generator. A test shows that interleaving evaluations leaves training
bit-identical.

*Lesson measured (E8): exploration is expensive when the episodes are
real.* Counting every training episode as real trading, starting ε at 1
loses more than a thousand episodes' worth of the optimal gain before it
pays off (break-even after ~12,000 episodes). Starting at 0.1 breaks even
after ~2,000 and learns just as well. Little exploration is needed here
because Q-values start at 0, which is optimistic for the bad actions
(never selling ends in a dump costing up to 500), so the greedy choice
tries them by itself. The default stays at 1 for tasks where rewards are
sparse and nothing is optimistic. The model-based agent earns 95–100% of
the optimal gain *while* learning (E11: after its first plan it explores
only 1% of the time; exploring 5% of the time cost 6–10% of the online
gain).

## 7. Supervision: the part most tutorials skip

### Held-out evaluation and the champion
Training returns are measured while exploring, so they understate the
policy. The trainer scores the greedy policy on fixed scenarios it never
trains on, and keeps the best policy seen so far as the **champion**:

* A challenger is promoted only if it scores at least as well on the same
  scenarios.
* The champion is re-scored every time, so after a change it is judged on
  the new world.
* **The champion is what gets deployed** (`deployed_act()`), while the
  learner keeps its own weights.

*Lessons measured:*
* **Restoring the champion destroyed learning.** An early version restored
  the champion into the learner at the end of every `run()`, which silently
  undid learning between calls (recovery stalled at 16%). A test now
  requires that training in chunks is bit-identical to training in one go.
* **The champion check saves real dips.** At episode 30,000 in the demo the
  learner dipped to 16%. The champion (45%) stayed deployed, and the
  learner recovered to 63% and then 67%.
* **Small evaluation sets pick the wrong winner.** Choosing champions on
  300 scenarios and measuring on 1,000 others showed a winner's curse.
  Larger evaluation sets are cheap here.

### Drift detection: suspect fast, confirm exactly
The trainer watches **surprise** = return obtained − return predicted at the
episode start. It works in two stages:

1. **Suspect:** a one-sided CUSUM test (Page, 1954) on standardized surprise,
   with allowance 0.3σ and threshold 16σ, against a baseline built only from
   samples at least 50 episodes old. The parameters were chosen by
   simulation: about one false alarm per 200,000 episodes, and a 0.55σ shift
   (what the market flip causes) caught after a median of 51 episodes.
2. **Confirm:** re-score the frozen champion on the held-out scenarios. In an
   unchanged world that score is reproduced bit for bit; only a changed world
   moves it.

The confirmation stage exists because of a measured failure. During ordinary
learning, value estimates are biased and still moving: early on the agent
predicts +31 and gets −9.6. At episode ~34,000 the learner's policy dipped, a
real performance drop the detector correctly flagged, but the world hadn't
changed. Acting on it reset exploration and cost 18 percentage points (48% instead of
67% at 40,000 episodes).
A fast detector can't tell "the world changed" from "my learning wobbled";
the champion check can.

A confirmed drift makes the agent explore again (ε = 0.5, decaying over
5,000 episodes), restart its step size, and clear its replay buffer, unless
the policy bank recognizes the new world.

**Good news is a change too (E13).** On the market-making task, a deeper
book made *every* policy earn more, so a test that only looked for falling
returns stayed quiet while the agent captured just 66% of the new optimum.
Two fixes: every evaluation now compares the champion's re-score with its
previous score (identical in an unchanged world, so a shift of more than 2
standard errors is a confirmed change, in either direction, with no false
alarms); and `DriftParams::two_sided` adds a mirror-image CUSUM for rises.
A bug surfaced on the way: every alarm, even one the re-score rejected,
reset the detector, which was then blind for 1,550 episodes. Now a false
alarm only re-centres it (`rebase()`).

### Policy bank: worlds seen before
On every confirmed drift the outgoing champion is banked, and older banked
policies are scored on the new world. One that beats the champion by 2
standard errors is redeployed at once, and the learner warm-starts from it.
In a market alternating between two regimes, each return was recognized
within 20–131 episodes, and the deployed policy was back at its old level
500 episodes after the switch. Without the bank it was still at −82% to
−109% then (`docs/ai/EXPERIMENTS.md` E3).

### Baseline guard: never ship worse than the simple thing
`set_baseline(policy)` gives the trainer a safe fallback such as TWAP. The
learned champion is deployed only once it beats the baseline on the
held-out scenarios by 2 standard errors of the paired difference, and the
check reruns after every evaluation and every confirmed drift. In a
weak-signal market (alpha 0.25), unguarded Q-learning deployed policies at
−35% to −106% of the optimal gain, i.e. worse than TWAP. With the guard,
TWAP stayed deployed on every seed, and in the default market nothing
changed (E6b).

*Lessons measured:*
* **Re-exploration length matters most.** A short boost (ε 0.3 for 600
  episodes) recovered only 10% of the new optimum after 20,000 episodes; the
  longer boost recovered about 43%.
* **Clearing replay helps only early.** It speeds up the first 2,500
  episodes after the flip (−0.3% vs −59%) and makes no difference later.

**In the demo**, the signal's meaning flips after 40,000 episodes:

| Episodes after the flip | With drift detection | Without |
|---|---|---|
| 0 | −140% (old knowledge is harmful) | −140% |
| 5,000 (drift detected after 44) | 18% | −89% |
| 25,000 | 46% | −40% |
| 40,000 | 51% | −34% |

## 8. How the same architecture maps onto LLM agents

A "self-improving" LLM agent fills the same slots with different parts:

| Slot | Here | In an LLM agent |
|---|---|---|
| Environment | market simulator | tools, users, codebases, web pages |
| Encoder | tile coding / RFF | a text embedding model |
| Episodic memory | k-NN over situation embeddings | a vector store of past attempts and outcomes (this repo's RAG engine) |
| Parametric learner | TD-updated weights | fine-tuning, or learned prompts / rules |
| Reward | mark-to-market P&L | test results, user feedback, an evaluator model |
| Policy | ε-greedy over Q | the LLM, conditioned on retrieved memories |
| Champion/challenger | held-out scenario scores | regression evals before shipping a new prompt or model |
| Drift detection | CUSUM on surprise, confirmed by champion re-score | monitoring eval scores and user signals in production |

The hard problems are the same in both:
* measuring improvement against a fixed yardstick;
* not shipping a policy that got worse;
* noticing when old lessons stop being true.

## 9. Extending it

* **A new task:** implement the `Environment` concept: `reset`, `step`,
  `features`, `kNumActions`, `kStateDims` and `kLo`/`kHi`. Nothing else
  changes. `market_making.hpp` is a worked example: a market maker quoting
  a bid and an ask (9 actions, state (t, inventory)), with an exact DP.
  The unchanged agent learns the optimal inventory skew (actor-critic:
  99–100% of the optimal gain after 5,000 episodes). It's much easier than
  execution because its optimal gain is 4 return standard deviations per
  episode, against 0.27 for execution: the ratio of gain to return noise,
  not the size of the state space, sets how hard model-free learning is
  (E12). A model-based market maker that counts its fills per quote
  distance gets to 98–100% after 3 episodes (`ModelBasedMarketMaker`,
  E15).
* **A new learner:** follow `TileQ` / `EpisodicMemory` / the actor-critic
  branch in `agent.hpp` and add a `LearnerKind`.
* **Real market data:** replay historical signals and prices in an
  environment. Be aware that the price-impact model then becomes an
  assumption, and that a backtest can't show the agent's own impact on the
  market.

# Task and algorithm specifications

The exact definitions behind every number in EXPERIMENTS.md: the tasks
(dynamics, rewards, defaults), how the optimum is computed, how the learners
update, and how results are scored. Symbols match the code.

## 1. Optimal execution (`ExecutionEnv`, `env.hpp`)

**State** (observation): `t` (steps taken, 0…H−1), `I` (lots left),
`g` (signal). **Actions:** 5. Action k sells q = min(round(sizesₖ · L/H), I)
lots, with sizes = {0, 0.5, 1, 2, 3} × the TWAP rate; action 2 is TWAP.

**One step** from (t, I, g) with action a, q lots sold, I' = I − q held:

1. The sale executes at the current price S minus temporary impact:
   cost(q) = impact · q^impact_exponent + fixed_cost (if q > 0).
2. Permanent impact: the price drops by permanent_impact · q.
3. If this was the last step (t + 1 = H), the remaining I' lots are dumped
   at cost terminal_impact · I'² (+ fixed_cost) and the episode ends.
4. Otherwise the price moves: ΔS = alpha · g + noise_sd · Z₁, and the signal
   evolves as g' = signal_rho · g + √(1 − signal_rho²) · signal_sd · Z₂.

**Reward** (change in mark-to-market wealth, minus the risk penalty):

    r = −cost(q) − permanent_impact · q · I'                     (every step)
        − terminal_impact · I'² (− fixed_cost)                   (last step)
        + I' · ΔS − risk_aversion · noise_sd² · I'²              (other steps)

With risk_aversion = 0 an episode's total reward equals
cash_final − L · S₀ (minus the implementation shortfall); tests check
this identity. The episode also ends early once I = 0. The first signal is
drawn from the stationary distribution, g₀ = signal_sd · Z.

**Defaults** (`ExecutionParams`): L = 100 lots, H = 20 steps,
impact 0.01, terminal_impact 0.05, impact_exponent 2, fixed_cost 0,
risk_aversion 0, permanent_impact 0, alpha 1, signal_rho 0.7,
signal_sd 0.1, noise_sd 0.05, S₀ = 100.

**Features** given to learners: (t/H, I/L, g/signal_sd), with ranges
kLo = (0, 0, −3) and kHi = (1, 1, 3).

## 2. Market making (`MarketMakingEnv`, `market_making.hpp`)

**State:** `t` (0…H−1), `q` (inventory, −Q…Q). **Actions:** 9, coded as
3 · bid + ask, each indexing distances = {0.5, 1, 2} from the mid; action 4
is symmetric at distance 1.

**One step** from (t, q) with distances (d_b, d_a):

1. The bid fills with probability fill_rate · e^(−decay · d_b), unless
   q = Q; the ask fills with probability fill_rate · e^(−decay · d_a),
   unless q = −Q (independent draws). A bid fill buys one unit (q + 1,
   earning d_b against the mid), an ask fill sells one (q − 1, earning d_a).
2. On the last step the inventory is liquidated at the mid, paying
   terminal_penalty · q'², and the episode ends.
3. Otherwise the mid moves by volatility · Z.

**Reward:** d_b · [bid filled] + d_a · [ask filled] + (last step:
−terminal_penalty · q'²; otherwise q' · Δmid − risk_aversion ·
volatility² · q'²). With risk_aversion = 0 the total equals the final cash
(tested).

**Defaults** (`MarketMakingParams`): H = 50, Q = 10, fill_rate 0.9,
decay 1, volatility 1, risk_aversion 0.05, terminal_penalty 0.5.
Features: (t/H, q/Q) in [0, 1] × [−1, 1].

## 3. Corridor (`ChainEnv`)

Positions 0…length−1 (default 10), start at 0, actions left/right, reward −1
per step, episode ends at the goal or after max_steps (60); with slip > 0 a
move is reversed with that probability. Optimal return (slip 0):
−(length − 1). Used for exact unit tests of the learners.

## 4. The exact optima

**ExecutionDP:** backward induction over (t, I, g):
V(t, I, g) = maxₐ Q(t, I, g, a), with
Q = E[r] + E[V(t + 1, I', g')]. Since E[ΔS | g] = alpha · g and the noise
has mean 0, E[r] = −cost(q) − permanent_impact · q · I' + I' · alpha · g −
penalties. The expectation over g' uses a 31-point quadrature of the
standard normal on [−4, 4] (weights ∝ density, normalized); V is linearly
interpolated on a grid of 121 signal points spanning ±4 · signal_sd. On the
grid, the expectation is applied as a precomputed banded matrix (A28).
`expected_start_value()` averages V(0, L, g₀) over the stationary g₀.
`policy_value(π)` and `evaluate_policy(π)` run the same recursion with π's
action in place of the max. `ExecutionDP(params, trade_costs, dump_costs)`
plans with arbitrary cost tables.

**MarketMakingDP:** backward induction over (t, q) with the four fill
outcomes per quote pair (no signal, so no quadrature; exact).

## 5. Learners (`agent.hpp`, `learners.hpp`)

**Tile coding** (`TileCoder`): each feature range is cut into `bins` cells
(default 8 per dimension) by `tilings` (default 8) grids, each offset by a
fraction of a cell. A state activates one tile per tiling.

**TileQ:** Q(s, a) = Σ over active tiles of w[tile, a]. An update toward a
target y adds (α / tilings) · (y − Q(s, a)) to each active weight.

* Targets: n-step returns (default n = 3):
  y = Σ_{k<n} γᵏ rₖ + γⁿ · maxₐ Q(sₙ, a), truncated at episode end
  (γ = 1).
* Experience replay: capacity 100,000; 4 replayed updates per real step.
* Step size α(e) = max(alpha_min, alpha / (1 + e / alpha_decay_episodes)),
  defaults 0.1, 0.003, 3,000 (e counts episodes since the last
  re-exploration).
* Exploration: ε falls linearly from eps_start (1) to eps_end (0.02) over
  eps_decay_episodes (1,500), and never reaches 0. Optional double
  Q-learning (off) and advantage learning: y ← y − k · (maxᵦ Q(s, b) − Q(s, a))
  (`advantage_learning`, default 0).

**ActorCritic:** a softmax policy π(a | s) ∝ exp(h(s, a) / T) over
tile-coded logits h, and a tile-coded critic V(s).
δ = r + γ · V(s') − V(s); the critic moves toward r + γ · V(s'); every logit
moves by actor_alpha · δ · (1[b = a] − π(b | s)) / T. Defaults:
actor_alpha 0.03, critic_alpha 0.1, T = 1, both step sizes scaled by
1 / (1 + e / 10,000) (floor alpha_min / alpha). It explores by sampling π;
ε-uniform actions are used only during a re-exploration boost (or a raised
temperature, with `ac_reexplore_temperature`).

**NeuralQ:** an MLP (`mlp.hpp`: features → 2 × 64 ReLU → 5 linear
outputs, He-uniform initialization) estimates Q(s, ·). Each finished
episode becomes n-step transitions (s, a, Σ γᵏ rₖ, s_{t+n}) in a replay
buffer (capacity `replay_capacity`); after `nn_warmup` transitions, every
step taken triggers one minibatch of `nn_batch` uniform samples, with target
y = R + γⁿ · maxₐ Q_target(s_{t+n}, a), a squared-error gradient on the
taken action's output, and one Adam step (`nn_lr`). The target network is
copied from the online one every `nn_target_sync` updates. Same ε schedule
as TileQ.

**EpisodicMemory:** k-NN (k = 8) over up to 4,096 remembered situations
(random-Fourier-feature embeddings, 64 dimensions), each with Monte Carlo
returns per action; LRU eviction.

**ModelBasedExecutionAgent** (`model_based.hpp`): fits, by weighted least
squares (weights 1 / max(1, I'²)) over every non-terminal step,

    r = alpha · (I' g) − holding · I'² − permanent · q I' − impact · q² [or a cost per order size]

plus terminal_impact from last steps and (rho, signal_sd) from the signal
path; then plans with ExecutionDP on the estimates. Schedule: 10 random
exploration episodes, then ε 0.01; re-plan after 20 episodes, doubling up
to 500. Cost models: Quadratic, PerSize, Shrunk (per-size costs shrunk to
the quadratic fit with 30 pseudo-observations). Optional forgetting and
change detection (E9).

## 6. Supervision (`trainer.hpp`, `drift.hpp`)

* **Held-out evaluation:** every eval_every (250) episodes, the greedy
  policy is scored on eval_episodes (300) fixed scenarios, Rng(9,000,000 + i).
* **Champion:** the best policy so far, re-scored at every evaluation; a
  challenger replaces it if it scores at least as well on the same
  scenarios. `deployed_act()` acts as the champion.
* **Drift:** a one-sided CUSUM test (optionally two-sided) on surprise =
  episode return − the agent's value of the start state, with allowance
  0.3σ, threshold 16σ, a baseline from samples ≥ 50 episodes old (EMA rate
  0.001, warm-up 1,500). An alarm is confirmed if the champion's re-score
  moved by more than 2 standard errors; a confirmed change also comes from
  any evaluation at which the champion's re-score moved that much.
* **On a confirmed change:** bank the champion (up to 8); recall a banked
  policy that beats it by 2 standard errors (then explore lightly: ε 0.05
  for 500 episodes), or else re-explore (ε 0.5 decaying over 5,000
  episodes), clear replay and restart the step-size schedule.
* **Baseline guard** (optional): deploy the baseline until the champion
  beats it by 2 standard errors of the paired difference.

## 7. Metrics

* **Share of the optimal gain:** (mean gain of the policy over the
  baseline) / (mean gain of the exact optimum over the baseline), both
  measured *paired* on the same scenarios (`compare()`: episode i of both
  policies uses Rng(seed + i)). The baseline is TWAP for execution and
  symmetric quoting for market making. 100% = optimal, 0% = baseline,
  negative = worse than the baseline.
* **Online gain** (E8, E11): Σ over training episodes of (return − exact
  value of the baseline), divided by the exact optimal gain per episode;
  +N after N episodes would be optimal.
* **Model check** (E7): z = (gain over TWAP the model predicts for its plan
  − gain measured on real scenarios, paired) / standard error; z > 4 means
  the model is wrong.
* **Tails** (E14): CVaR α = mean of the worst α fraction of episode
  returns, on cash outcomes (risk penalty off).
* **Seeds:** experiments report ranges over seeds (usually 1–3 or 1–5);
  tests pin one seed and assert with margins.

# Lessons, distilled

The experiment log (`EXPERIMENTS.md`, E0–E14) is long. These are its
cross-cutting lessons, each with the measurement behind it. They're about
building learning systems in general, not just this task.

## Measuring

1. **Score against an exact optimum, as a share of the optimal gain.**
   "Reward went up" can't be compared across runs; "67% of optimal" can
   (A1). When the optimum is computable (a DP here), compute it.
2. **Pair your comparisons.** Episode returns have sd ≈ 55, much larger than
   the differences between good policies; common random numbers make
   differences of a few percent measurable (A2). Pairing also made a model
   check ~10× more sample-efficient: 100 episodes instead of ~1,500 (E7c).
3. **Count what learning costs, not only what it ends with.** With every
   training episode counted as real, ε starting at 1 lost over a thousand
   episodes' worth of the optimal gain before paying off (E8).
4. **Look at the tail you care about directly.** A policy more volatile
   than TWAP had a far better worst 5% (−66 vs −117), and a variance
   penalty that halved the sd barely moved the tail (E14).
5. **Unpaired online sums are noisy.** Cumulative gains over 20,000
   episodes carry about ±500 of noise; read them to ~2.5% (E11).

## Learning

6. **Model-free difficulty is set by gain-to-noise, not by the state
   space.** Execution: optimal gain 0.27 return-sds per episode, TileQ
   plateaus near 70%. Market making: 4.07, TileQ reaches 97–99% and
   actor-critic 100% in 5,000 episodes (E12).
7. **The plateau is target noise, not capacity, but how the approximator
   averages noise matters.** The default tiles can represent a 99.5% policy
   (E2b), yet coarser tiles learned better (76–77% vs 65–69%) and a small
   neural network better still (84–89%), with the same targets (E16).
   Multi-step returns helped too (n = 3; E2a).
8. **A model that's right beats any model-free learner by orders of
   magnitude:** 99–100% after 20–50 episodes vs ~70% after 40,000 (E1);
   even on the task model-free learning finds easy, 3 episodes vs 5,000
   (E15).
9. **A model that's wrong is worse than no model,** and gets worse with
   more data, because its plan exploits its own error (25% after 300
   episodes vs 43% after 20; E7a). Shrinkage toward a simple prior makes
   flexible models safe with little data (E1c).
10. **RL fine-tuning can't hold a near-optimal policy against noisy
    targets.** TD jitter (≈ √(α/2)·σ ≈ 2) exceeded the action gaps (< 1),
    so fine-tuning wrecked a distilled 99% policy within 2,500 episodes
    (E7d).
11. **Little exploration is often enough.** Zero-initialized values were
    optimistic about the bad actions, so greedy selection explored them;
    ε 0.1 learned as well as ε 1 at a fraction of the online cost (E8). For
    the model-based agent the ongoing ε 0.05, not the initial exploration,
    was the cost (E11).

## Deploying

12. **Deploy a champion, not the learner.** Learning wobbles; the champion
    only changes when a challenger beats it on the same held-out scenarios
    (A6).
13. **Never deploy below the simple baseline.** In a weak-signal market,
    Q-learning's champions were 35–106% *worse* than TWAP; a guard that
    requires beating the baseline by 2 standard errors fixed it at no cost
    elsewhere (E6b).
14. **Check a model before trusting its plan.** A wrong model is always
    optimistic about its own plan (the optimizer's curse), so "predicted
    gain > realized gain" is the signature to test for (E7c).
15. **When the model may be wrong, combine:** distill its plan into a
    model-free learner, fine-tune on real rewards, and guard with the plan
    as the baseline. 100% when the model is right, never below the plan
    when it isn't (E7d).

## Changing worlds

16. **Suspect fast, confirm exactly.** A CUSUM test on surprise reacts in
    tens of episodes but can't tell "the world changed" from "my learning
    wobbled"; re-scoring the frozen champion on fixed scenarios can, because
    in an unchanged world it reproduces exactly (A7).
17. **Good news is a change too.** A market that got better went unnoticed
    by a detector that watched for drops; the champion's re-score catches
    changes in either direction (E13).
18. **A detector must not go blind after a false alarm.** Resetting on
    every alarm left a 1,550-episode blind spot that a real change fell
    into (E13).
19. **Remember old worlds.** A bank of past champions recognized returning
    regimes within 20–131 episodes (E3), and at 99–100% on the second task
    (E13).
20. **Few parameters adapt fast.** After a flip the model-based agent was
    back at 95–100% within 20 episodes (change detection + reset), against
    5,000 episodes for the model-free agent to reach 18% (E9).

## Offline evaluation

21. **Importance sampling fails at long horizons.** At 20 steps, almost no
    logged episode follows a different deterministic policy for long
    (effective sample size ≈ 0), and errors stayed at 45–2,968% of the
    optimal gain with 10,000 logs (E10).
22. **So offline evaluation rests on a model, and the model must be
    checked:** the direct method was accurate to 2–4% with the right model
    class and biased by up to 62% with the wrong one, regardless of data
    volume (E10).

## Engineering

23. **Bugs hid in plain sight, and measurement found them:** a planner that
    received hidden market parameters (A11, and nearly again in E7); an
    exploration phase twice as long as configured (E11); a detector blind
    after false alarms (E13). Each now has a regression test.
24. **Speed up the inner loop before scaling experiments.** A precomputed
    banded expectation made the DP ~9× faster with identical decisions, and
    the slowest tests 4–10× faster (A28).
25. **Decompose the noise before reducing it.** A textbook control variate
    for the price innovation did nothing here, because the signal path, not
    the innovation, carried ~95% of the return variance; where the
    innovation was large, the same trick worked (E17).
26. **Tune globally, validate out of sample.** A local optimizer's result
    depended on its start; a global search plus held-out seeds and
    bootstrap intervals gave a reliable improvement (37% → 59%), and a
    response surface over the trials recovered the earlier lessons (E18).
27. **Independent reviewers find what the author doesn't.** Three review
    agents found 14 bugs in code that already had ~98% line coverage and a
    differential test suite: among them a heap overflow reachable through
    a config value and through a forged index file, a bit-exactness
    violation in IVF, and an RL schedule off by one doubling (A40, A41,
    R13–R17). One bug was found independently by two of them.
28. **Rank learners under one protocol, with intervals.** Numbers gathered
    by different probes (seeds, evaluation sets, deployed vs final policy)
    don't compare. One protocol (8 seeds, deployed champion, the same
    held-out scenarios, bootstrap intervals) separated the top three
    learners cleanly and showed that a configuration tuned for 10k episodes
    has a wide spread at 40k (E21).

# Research notes: noisy-target RL, execution and market making

A literature review written by a research agent for this project (after
E16), mapping published results onto what the experiments measured, and
ranking next experiments. **Caveats:** the environment's network policy
blocked arxiv.org, so most claims were checked against abstracts,
proceedings pages and search-indexed text. Numbers marked † come from
secondary summaries; confirm them in the paper before relying on them.
**[E]** marks an established, published result; **[I]** marks inference
about this codebase.

## 0. The number that frames everything

**[I]** The samples needed to detect an effect scale like (noise/effect)².
The two tasks differ in gain-to-noise by (4.07/0.27)² ≈ 227 (E12). If
actor-critic needs ~5k episodes on market making, a naive scaling puts
execution at ~10⁶ for the same precision. So 75–77% at 200k episodes (E2)
is roughly what you'd expect: the execution task is hard because of
statistical estimation, not representation or exploration.

**[E]** The closest analytical ancestor of the execution task is Bertsimas
& Lo's model with an AR(1) information variable [BL98]; there too the
signal-adjusted strategy saves only a sliver of cost (about 241.46M vs
241.26M in a Nikkei example†).

## 1. Why a small MLP can beat tile coding when both can represent Q*

Approximation error is ruled out (tiles fitted to Q* give 99.5%). What's
left: variance of the estimates, and bias from the learning dynamics.

* **(a) Pooling: effective samples per parameter.**
  * **[E]** Tile coding generalizes locally: each weight is updated only
    by samples in its tile [SB18 §9.5.4].
  * **[E]** Tile-coding the inputs of a neural net makes it "generalize
    more locally", with less interference [GYRS18, GRLGW20].
  * **[E]** ReLU networks are biased toward low-frequency functions
    (spectral bias) [Rah19].
  * **[I]** With roughly white target noise across states, a
    smoothness-biased learner acts as a low-pass filter. The MLP has about
    4.7k parameters, while a fine tiling gives each weight far fewer
    effective samples.
* **(b) Sharing across actions.**
  * **[E]** The dueling paper argues that action gaps are tiny relative to
    Q values, so small update noise reorders actions [Wang16].
  * **[E]** VA-learning learns V faster than A "as the former is shared
    across all actions" [Tang23].
  * **[E]** A 2026 value-sharing layer increases action gaps and reduces
    overestimation [Nag26].
  * **[I]** With per-action tile weights, Q(s,a) − Q(s,a′) is estimated
    from *disjoint* noisy samples, and ε-greedy starves non-greedy actions.
    The MLP's shared torso estimates the action-dependent part through
    common features. This is the leading hypothesis.
* **(c) Optimizer and averaging.**
  * **[E]** Adam's update factorizes into a sign and a variance-adaptation
    factor that shrinks the step as relative gradient variance grows
    [BH18, KB15].
  * **[E]** The step-size schedule governs Q-learning's convergence rate
    [EDM03].
  * **[I]** The replay result (32 updates per step worse than 4) fits a
    constant-α noise floor. The weights are an exponential moving average
    over about 1/α updates, so more updates per transition at the same α
    shrinks that window in distinct transitions, and the weights get
    noisier.
  * **[I]** Target variance scales with inventory², so one α is wrong for
    high-inventory tiles; per-parameter normalization corrects that.
  * (E16 measured: SGD instead of Adam still reached 67–83%, so this is at
    most part of the story.)
* **(d) Target networks and the deadly triad.**
  * **[E]** Multi-step returns, double Q and target networks reduce "soft
    divergence"† [vH18].
  * **[E]** A target network with Polyak updates gives convergent linear
    Q-learning [ZYW21].
  * **[I]** With a 20-step horizon and 3-step returns, divergence is
    unlikely to be the driver. (E16 measured: no effect.)
* **(e) Bias at the TD fixed point.**
  * **[E]** Oracle tests of Q-learning found function-approximation error
    matters little with expressive networks, while the sampling
    distribution matters [Fu19].
  * **[I]** Tiles fitted to Q* give the *projection* of Q*. Semi-gradient
    off-policy Q-learning converges to the *projected Bellman fixed point*
    [SB18 ch. 11], which can induce a different greedy policy. Only a
    noise-free run separates bias from variance.

Ablations that discriminate between these:

| Ablation | Points to |
|---|---|
| Tile Q-learning with exact expected targets (integrate the noise out in the simulator) | still ~75%: bias (e); close to 99%: variance |
| Tiles with per-weight Adam/RMSProp, or α = 1/n^0.7 per tile, or minibatch-averaged updates | large gain: (c) |
| Tiles with 32 replays at α/8 | ≥ 4 replays at α: (c), the replay noise floor |
| Tiles with V on fine tiles + A on coarse tiles, or the action as a 4th tiled dimension | large gain: (b) |
| DQN on tile-coded inputs; DQN with separate per-action networks | drop: (a), (b) |
| Linear Fourier basis trained with Adam | matches the MLP: (a) without nonlinearity |
| Ridge LSTD-Q or backward fitted Q iteration on the same data | the lowest-variance linear result: the ceiling for tiles at this data size [LP03] |

## 2. DQN improvements that target noisy targets and action gaps

Effect sizes are median human-normalized Atari scores from Rainbow's
Table 2 [Hes18] unless noted (separately published agents, not clean
ablations; in Rainbow's ablation, prioritized replay and multi-step mattered
most†).

| Method | Mechanism | Reported effect | Plausible here? |
|---|---|---|---|
| Double DQN [vHGS16] | decouples selection from evaluation; the max over noisy estimates is biased upward | 79% → 117% | medium-high. [I] Overestimation is largest for actions that keep more inventory (noise ∝ inventory²), predicting too-slow selling: compare learned vs optimal inventory paths |
| Dueling [Wang16] | V and A streams; robust to small gaps | 151% (with Double DQN) | high, cheap |
| Advantage learning / consistent Bellman [Bel16] | widens gaps by lowering suboptimal actions' values; optimal policies preserved | a one-line change that "significantly outperform[s]" DQN on 60 games | high; also works with linear tiles |
| Munchausen RL [VPG20] | adds τ·log π to the reward: implicit KL regularization (averages Q over iterations) and gap increase | beats DQN by a large margin and C51; M-IQN beats Rainbow | high: the error bound depends on the norm of the *averaged* errors [Vie20], which suits this noise |

| HL-Gauss classification loss [Far24] | cross-entropy against a histogram of the target | more robust to reward noise†; same as MSE for deterministic dynamics | moderate, cheap |
| Averaged-DQN [ABS17] | target = mean of the last K networks | lower target-error variance | moderate; similar to Polyak |
| Ensembles: Bootstrapped DQN [Osb16], Maxmin [Lan20], REDQ [Chen21] | several heads; min over a subset controls bias | REDQ makes high update-to-data ratios work | moderate; addresses the replay-ratio failure |

  certainty-equivalence advantage [TR19] predicts.

## 4. Variance reduction and structure exploitation

* **4.1 Remove the exogenous price innovation (a control variate).**
  * **[I]** With execution price S − ηa and mark-to-market reward,
    r = −ηa² + q′(μ(x) + ε′), where μ is the signal-implied drift and ε′
    the price innovation. The term q′ε′ has zero mean given (s, a), so
    subtracting it leaves Q* *unchanged* (when μ is known) and removes the
    dominant noise; what remains is the randomness of the next signal.
  * **[I]** With μ estimated, the bias is q′(μ − μ̂): one regression
    parameter, which the model-based agent learns in ~20 episodes.
  * **[E]** Removing exogenous reward components speeds up learning
    [DTC18]. Input-dependent baselines are unbiased and reduce variance
    [MVSA19]. Baselines are additive control variates [GBB04].
* **4.2 All-action updates with shared noise.**
  * **[I]** Impact is temporary, so the price path doesn't depend on the
    action. For each transition, targets for *every* action can be computed
    with the same realized ε: the noise in action differences falls from
    ~q·ε to ~(a − a′)·ε. This needs the impact function (known or learned).
  * **[E]** See [Sin23] (hindsight learning in exogenous MDPs), [PCG20]
    (counterfactual augmentation) and NFK06.
* **4.3 Afterstates.**
  * **[E]** [SB18 §6.8]; [Pow09].
  * **[I]** Q(t,q,x,a) = −ηa² + W(t, q − a, x): one function W serves all
    actions. (E2 tried a version of this and logged it as a negative
    result.)
* **4.4 Common random numbers and antithetics.**
  * **[E]** PEGASUS [NJ00]; [Gla03]. This project already uses common
    random numbers; antithetic (mirrored-noise) paths would add more.
* **4.5 Potential-based shaping.**
  * **[E]** Shaping with a potential Φ preserves optimal policies [NHR99]
    and equals Q initialization in the tabular case [Wie03].
  * **[I]** Mark-to-market reward is already shaping with Φ = q·S; shaping
    toward an analytic value makes the learner fit a residual but doesn't
    remove noise.
* **4.6 Better estimators.**
  * **[E]** Zap Q-learning [DM17]; variance-reduced Q-learning [Wai19];
    Polyak–Ruppert averaging [PJ92]; LSTD/LSPI [LP03].

## 5. Ranked next experiments (as proposed)

1. **Evaluation hygiene:** antithetic paths; acting with averaged weights;
   ≥ 10 seeds with interquartile means and bootstrap intervals [Aga21].
2. **The exogenous-innovation control variate (§4.1)** for tiles, DQN and
   actor-critic. Expected: the largest single gain; tile Q-learning above
   90% at 40k if variance is the bottleneck.
3. **An oracle / noise-dial test [Fu19]:** exact expected targets, then
   targets with k·(sampled − expected) noise, k from 0 to 1, to separate
   bias from variance.
4. **Step-size and estimator ablations for tiles:** α/R with the replay
   ratio, per-weight Adam, 1/n^0.7, Polyak–Ruppert averaging, ridge LSTD-Q.
5. **Sharing across actions:** V + A decomposition for tiles; per-action
   networks and tile-coded inputs as negative controls for DQN.
6. **Gap-increasing and averaging targets:** advantage learning,
   Munchausen, dueling, Double Q; check the learned inventory path.
7. **All-action updates and afterstates (§4.2–4.3)** as a semi-model-based
   tier, to locate the boundary between model-free and model-based here.

## E1. Model-based agent: learn the market, then plan

* **Hypothesis:** an agent that knows the *form* of the model, but not its
  numbers, can estimate them by regression and plan with the DP. It should
  reach near-optimal play in about 100 episodes instead of tens of
  thousands. A wrong form should make it worse than model-free learning.
* **Code:**
  * `include/rag/agent/model_based.hpp` (`ModelBasedExecutionAgent`,
    `CostModel`);
  * `ExecutionParams::impact_exponent` and `fixed_cost` for alternative
    markets;
  * `ExecutionDP` accepts learned cost tables.
* **Tests:** `tests/model_based_tests.cpp`.

### E1a. Correct model form (quadratic impact)

* **Estimation:**
  * (impact, alpha) by weighted least squares on step rewards, with weights
    1/max(1, I')²;
  * terminal impact from last steps;
  * (rho, sd) from the AR(1) regression of each signal on the previous one.
* **Parameter recovery:** after 1,000 episodes, impact 0.0100 (true 0.0100),
  terminal 0.0500 (0.0500), alpha 1.00 (1.00), rho 0.70–0.71 (0.70), sd
  0.099–0.101 (0.100).
* **Share of the optimal gain**, seeds 1–3:

  | Episodes | Share |
  |---|---|
  | 10 | 87–100% |
  | 20 | 99.6–100% |
  | ≥ 50 | 100% |

* **Model-free for comparison:** TileQ reaches 67% after 40,000 episodes.
* **Conclusion:** when the assumed form is right, model-based learning is
  roughly 1,000× more sample-efficient here. A handful of numbers to
  estimate, plus exact planning, beats learning a value for every state.

### E1b. Wrong model form

Markets where impact isn't quadratic, or every order pays a fixed cost.
Model-based agents trained 1,000 episodes, TileQ 40,000; shares of each
market's own optimum:

| Market | Quadratic model | Per-size model | TileQ |
|---|---|---|---|
| quadratic (correct form) | 100% | 100% | 66% |
| impact ~ q^1.5 | 99% | 100% | 73% |
| linear impact (exponent 1) | 99% | 100% | 69% |
| convex impact (exponent 3) | 83% | 100% | 38% |
| fixed cost 1.5 per order | 53% | 100% | 61% |
| exponent 1 + fixed 1.5 | 57% | 100% | 87% |
| exponent 3 + fixed 1.5 | 53% | 100% | 63% |

* **Mild misspecification is harmless.** With 5 discrete order sizes, a
  wrong-but-close fit rarely changes the best action.
* **Strong misspecification costs 17–47 points**, and the planner makes it
  worse by exploiting its model's errors: it trades the sizes its model
  underprices.
* **"Per-size"** learns a free cost for each order size traded, in closed
  form with alpha profiled out. It assumes no curve shape and gets 100%
  everywhere.
* **Measurement bug, caught and fixed:** the first run showed −64% for the
  quadratic model on convex impact. The agent's `structure` parameters had
  leaked the true `impact_exponent` and `fixed_cost` into its planner,
  combined with a coefficient fitted under the quadratic assumption.
  `replan()` now forces the assumed form, and the test
  `HiddenMarketParametersDoNotLeakIntoThePlan` feeds two agents identical
  experience with different hidden parameters and requires identical plans.

### E1c. Flexibility needs data; shrinkage makes it safe

Hard market (exponent 3 + fixed 1.5), mean over 5 seeds:

| Episodes | 5 | 10 | 20 | 50 | 100 | 300 |
|---|---|---|---|---|---|---|
| Quadratic | 43% | 47% | 52% | 56% | 55% | 55% |
| Per-size | −1601% | −641% | −198% | 100% | 100% | 100% |
| Shrunk (k = 30) | 78% | 87% | 93% | 97% | 98% | 99% |

In the correct quadratic market, Shrunk matches the quadratic model
(85 / 94 / 97 / 100%); per-size there is −535 / −168 / −22 / 100%.

* **Per-size is bimodal with little data.** At 10 episodes, seeds 1–10
  scored 97, −1701, 97, −1809, 97, 98, 98, −1782, 99 and −1440%. The planner
  exploits wild cost estimates for rarely traded sizes.
* **Shrinkage** (`CostModel::Shrunk`) blends each size's estimate with the
  quadratic prediction, weighted by its trade count; unseen sizes fall back
  to the prior. It was never catastrophic: 82–89% at 10 episodes on every
  seed, 91–95% at 20.
* **Conclusion:** the right amount of model structure depends on the data.
  Strong assumptions learn fast and plateau when wrong; flexible models are
  eventually right but dangerous early. Empirical-Bayes shrinkage gets most
  of both. The general lesson for planning agents: a planner exploits
  whatever its model gets wrong, so uncertain parts of the model need to be
  pessimistic or pulled toward a prior.

At 200k episodes, n = 3 reaches 75.8 / 76.8 / 74.9% (n = 1: 72%). **n = 3
is now the default.** The hypothesis is rejected, though: Monte Carlo
targets (no bootstrapping, no max-bias) plateau too.

### E2b. The representation ceiling: fit the true Q* directly

Fitting tile-coded Q to the DP's exact Q*(s, a) by plain regression, on
states from an exploring policy (80% optimal, 20% random), all 5 actions per
state, 100k episodes:

| Tiles | Weights per action | Greedy share |
|---|---|---|
| 8×8×8 × 8 tilings (default) | 5,832 | **99.5%** |
| 8×10×12 × 8 | 10,296 | 99.5% |
| 12×12×12 × 8 | 17,576 | 99.7% |
| 16×16×16 × 16 | 78,608 | 99.9% |

**The representation is not the bottleneck.** The earlier finding that finer
tiles do worse in RL is about learning (fewer samples per weight), not
capacity.

### E2c. Ablation: noise vs coverage (40k episodes)

| Targets | Actions updated per visited state | Share |
|---|---|---|
| exact Q* | all 5 | 99.4% |
| exact Q* | only the one taken | **−92.7%** |
| one sampled return (then optimal) | all 5 | **65.7%** |
| one sampled return | only the one taken | −51.9% |

* **Noise alone reproduces the plateau.** Sampled returns have sd ≈ 20–50,
  against action-value gaps that are often below 1.
* **Uneven coverage is catastrophic on its own.** Actions rarely taken in a
  region keep their initial value 0, which beats the true (negative) values,
  so the greedy policy picks the least-known action. In RL, ε-exploration
  partly repairs this.

### E2d. Fixes tried for the noise

| Idea | Result |
|---|---|
| Afterstates, Q = C[q] + W(t, I − q, g), sharing W across actions | 43–51% at 10k (better than n = 1), 61–67% at 40k (same plateau) |
| Polyak tail-averaging of weights (second half of training) | worse at 40k (n = 1: 31–48% vs 46–66%; n = 3: 64–71% vs 67–73%), because the iterates are still improving. At 200k it protected against one late dip (64% → 78%); the champion mechanism already covers that. |
| Lower step-size floor (0.001, 0.0003) | no effect up to 200k: the 1/(1 + ep/3000) schedule hadn't reached the floor |

### Conclusions

* **The gap is variance, not representation.** The model-free learner sees
  each state-action value through one noisy sample at a time.
* **Model-based learning (E1) closes the gap** because it estimates 5
  numbers from all transitions jointly and plans exactly: 100% in 20–50
  episodes.
* **For model-free learning, the remaining levers** are variance reduction:
  control variates, or counterfactual updates using the fact that the price
  move doesn't depend on the action.

## E3. Policy bank: recognizing a regime seen before

* **Hypothesis:** markets alternate between regimes. Keeping past champions
  and re-scoring them on a confirmed drift should let the agent redeploy a
  matching policy at once, instead of relearning.
* **Code:** `TrainConfig::policy_bank` (default on), `bank_capacity`,
  `recall_epsilon`, `recall_episodes`; `Trainer::recall_from_bank()`.
* **Mechanism:** on a confirmed drift,
  1. the outgoing champion is banked;
  2. every older banked policy is scored on the held-out scenarios;
  3. if one beats the re-scored champion by 2 standard errors, it becomes
     the champion, the learner warm-starts from it, and exploration is light
     (ε 0.05 for 500 episodes);
  4. otherwise, the agent re-explores normally (ε 0.5 for 5,000 episodes).
* **Tests:** `AgentPolicyBank.*`.
* **Setup:** 20k episodes in regime A (alpha +1), then the regime alternates
  B (alpha −1) / A / B / A every 10k episodes. Each cell is the deployed
  policy's share of the current regime's optimal gain:

  | Switch to | Bank on: +500 | +2,000 | +10,000 | Bank off: +500 | +2,000 | +10,000 |
  |---|---|---|---|---|---|---|
  | B (first) | −126% | −6% | 25% | −126% | −6% | 25% |
  | A | **59%** (recalled at +131) | 59% | 59% | −82% | 20% | 50% |
  | B | **25%** (recalled at +20) | 26% | 36% | −109% | 6% | 30% |
  | A | **59%** (recalled at +20) | 59% | 59% | −86% | 21% | 41% |

* **Conclusion:** on its first visit to a regime the bank changes nothing.
  On every return it's recognized within 20–131 episodes, and the deployed
  policy is back at its previous level instead of losing money for
  thousands of episodes. This only works because drift *confirmation*
  re-scores policies on fixed held-out scenarios; the same evaluation
  machinery answers "which known world is this?".

## E4. Risk-averse execution (mean-variance)

* **Hypothesis:** with a risk penalty, the optimal policy sells earlier;
  learners should discover how much earlier. The model-based agent needs a
  holding-cost term to stay optimal.
* **Code:**
  * `ExecutionParams::risk_aversion` λ: each step's reward is reduced by
    λ·noise_sd²·I'², the variance the held inventory adds. The penalty is in
    the reward only; cash accounting is unchanged. The DP includes it.
  * The model-based agent now solves one weighted normal-equations system
    (Gaussian elimination) over alpha, a holding cost κ (regressor −I'²), and
    either the quadratic impact or one cost per order size.
* **Tests:** `ModelBased.LearnsTheRiskPenalty`,
  `AgentRisk.FrontLoadsMoreWhenRiskAverse`.

| λ | DP optimum: mean cash / sd / lots sold in steps 0–4 | TileQ 40k: share, sd | Model-based 300 eps: share, fitted κ (true) |
|---|---|---|---|
| 0 | +9.3 / 58.7 / 26.5 | 70%, 52.1 | 100%, 0.00000 (0) |
| 0.01 | +9.3 / 57.7 / 28.6 | 66%, 50.7 | 100%, 0.00002 (0.000025) |
| 0.05 | +8.6 / 54.0 / 36.5 | 73%, 46.3 | 100%, 0.00011 (0.000125) |
| 0.2 | +2.8 / 42.9 / 55.0 | 91%, 39.2 | 100%, 0.00049 (0.0005) |
| 1.0 | −8.4 / 28.2 / 72.9 | 100%, 27.7 | 100%, 0.00249 (0.0025) |

"Share" is the share of the risk-adjusted optimal gain over TWAP.

* **The DP traces the classic Almgren–Chriss trade-off:** more risk aversion
  means selling earlier (26 → 73 lots in the first 5 steps), lower variance
  (sd 59 → 28) and a lower mean (+9.3 → −8.4).
* **Both learners front-load as λ grows.**
* **Strong risk aversion makes model-free learning easy.** The best policy
  becomes "sell fast", which leaves less to gain from the noisy signal:
  TileQ goes from 70% to 100%.
* **The model-based agent recovers κ to within ~2%** at λ ≥ 0.2, and stays at
  100%.

## E5. Policy gradient: actor-critic

* **Hypothesis:** learning a policy directly, with a critic's TD error as the
  advantage, copes better with target noise than learning Q-values, because
  the actor only needs relative preferences.
* **Code:**
  * `LearnerKind::ActorCritic`: a softmax policy over tile-coded logits plus
    a tile-coded critic V(s), with 1-step TD error as the advantage and
    `actor_alpha` / `critic_alpha` / `temperature` / `ac_decay_episodes`.
  * On-policy: exploration is sampling from the policy (ε applies only
    during re-exploration); no replay. `value()` is the critic, so drift
    detection and champions work unchanged.
* **Tests:** `AgentActorCritic.*`.

Standalone probe (seeds 1–5 at 10k/40k, 1–3 at 200k):

| Actor / critic step, temperature | 10k | 40k | 200k |
|---|---|---|---|
| 0.03 / 0.1, T = 1 | 55–76% (median 75) | 79–84% | **86–89%** |
| 0.01 / 0.1, T = 1 | −884% to −374% (policy still near-random) | 59–63% | |
| 0.003 / 0.1 | about −600% | about −600% | |
| 0.05–0.1 / 0.1 | 69–72% | 74–84% | |
| 0.03 / 0.03 (slow critic) | −427% to −310% | 73–77% | |

The step-size schedule matters (library Trainer, seeds 1–3):

| Annealing half-life | 10k | 40k |
|---|---|---|
| 3,000 episodes (the TileQ default) | −235%, 7%, −2% | −24%, 84%, 78% |
| 5,000 | 57–77% | 79–83% |
| **10,000 (default `ac_decay_episodes`)** | **75–78%** | **80–86%** |
| 20,000 | 75–79% | 82–84% |

* **Actor-critic is the best model-free learner here.** At 200k episodes it
  reaches 86–89%, against 75–79% for 3-step Q-learning, and it's far ahead
  early (75% vs 47–50% at 10k).
* **It's fragile in a different way.** Too small an actor step, or annealing
  too early, leaves the policy near-uniform, which in this task loses
  heavily. A learner whose failure mode is "stays random" needs its
  schedule chosen with care.

## E6b. A baseline guard: never deploy below TWAP

* **Code:** `Trainer::set_baseline(policy)`. With a baseline set,
  `deployed_act()` uses the baseline until the champion beats it on the
  held-out scenarios by more than 2 standard errors of the paired
  difference. The check reruns at every champion evaluation and after every
  confirmed drift, so a champion that stops working falls back to the
  baseline. `learned_policy_deployed()` reports which one is live;
  `EvalPoint::learned_deployed` logs it.
* **Test:** `AgentSafety.NeverDeploysAPolicyWorseThanTheBaseline`.
* **Measured** (TileQ, 20k episodes, seeds 1–5; deployed share of the
  optimal gain; probe `guard_probe.cpp`):

| Market | Unguarded | Guarded | Learned policy deployed |
|---|---|---|---|
| default | 52 / 61 / 59 / 60 / 58% | identical | 5 of 5 |
| alpha 0.25 | −58 / −66 / −75 / −35 / −106% | **0% (TWAP) on every seed** | 0 of 5 |
| rho 0 | −8 / 16 / 4 / 9 / 25% | 0 / 0 / 0 / 0 / 25% | 1 of 5 |

* **The guard removes the downside** (worst case −106% → 0%) and costs
  nothing where learning works.
* **It's conservative:** in the rho-0 market it held back three small gains
  (4–16%) that weren't statistically distinguishable from TWAP on 600
  held-out scenarios. More evaluation scenarios would release them sooner.

## E7. Outside the model class: permanent impact

* **Question:** E6 found the model-based agent at 100% everywhere, but every
  market there was inside its model class. What happens when the market has
  structure the model lacks, and can the agent tell?
* **Code:**
  * `ExecutionParams::permanent_impact` γ: each lot sold lowers the price for
    the rest of the episode, so the inventory still held loses γ·q·I'. The DP
    includes it.
  * `ExecutionDP::policy_value(policy)`: exact expected value of any policy
    under a model, by backward induction with the policy's action.
  * `ModelBasedExecutionAgent::Config::learn_permanent_impact` (regressor
    −q·I'), `check_model()`, `plan()`.
  * `Agent::distill(sim, teacher_q, episodes, seed)`: a supervised warm start
    of the tiles from a teacher's Q-values.
  * `evaluate()`/`compare()` moved to `evaluate.hpp`, so the model-based
    agent can use them without the trainer.
* **Tests:**
  * `ExecutionCosts.PermanentImpactKeepsTheAccountingIdentityAndTheDpIsExact`;
  * `ModelBased.LearnsPermanentImpactAndAWrongModelGetsWorseWithData`;
  * `ModelBased.CheckModelFlagsAMissingTerm`;
  * `AgentWarmStart.DistilledModelPlusGuardIsBestOfBoth`.

### E7a. A missing term reverses the ranking

Model-based agent (Shrunk, 300 episodes) without the permanent term vs the
model-free learners (40k episodes), seed 1 (probe `e7_probe.cpp`):

| γ | DP gain over TWAP | Model-based, no term | TileQ | ActorCritic |
|---|---|---|---|---|
| 0 | +16.3 | 100% | 70% | 82% |
| 0.005 | +17.9 | 47–55% (6 seeds) | 70% | 85% |
| 0.01 | +19.7 | 22–27% (6 seeds) | 80% | 82% |
| 0.02 | +23.9 | 22% | 83% | 91% |

* **This is the bias–variance trade-off of model-based RL, measured.** The
  model-free learners pay ~20–30 points of variance everywhere but no bias;
  the model-based agent has no variance to speak of, but its bias is
  unbounded once its model is wrong.
* **The omitted term goes into the wrong coefficients:** a fitted holding
  cost (0.0007–0.002 for a true 0) and an inflated alpha (1.18–1.28 for a
  true 1.0).
* **More data makes the wrong model worse** (5 seeds, γ = 0.01): 43% at 20
  episodes, 37% at 50, 25% at 300. The plan exploits the model's error, so
  the data it collects grows increasingly one-sided: a closed-loop
  identification bias.
* **A near-miss bug of the A11 kind:** the first version of this probe let
  the true γ leak from `structure` into the planner (replan() didn't
  override the new field). The leak regression test now scrambles every
  market field the planner reads.

### E7b. Expanding the model class fixes it, at almost no cost

With `learn_permanent_impact` (5 seeds; probe `e7_cost.cpp`):

| Market | Episodes | Without the term | With it | Fitted γ |
|---|---|---|---|---|
| γ = 0.01 | 20 | 43% | 93% | 0.0101 |
| γ = 0.01 | 50 | 37% | 99.8% | 0.0102 |
| γ = 0.01 | 300 | 25% | 99.9% | 0.0100 |
| default | 20 / 50 / 300 | 96.0 / 100.0 / 100.1% | 96.4 / 100.0 / 100.0% | ~0.0001 |
| λ = 0.2 | 20 / 50 / 300 | 99.0 / 99.7 / 100.0% | 99.0 / 99.4 / 99.9% | ~0.0001 |

The extra parameter costs at most 0.3 points where it isn't needed, and is
on by default. It does blur the holding-cost estimate on one test seed
(0.00057 for a true 0.0005), because front-loading plans make q·I' and I'²
correlated.

### E7c. The agent can tell when its model is wrong

`check_model(market, n, seed)` compares the gain over TWAP that the model
predicts for its own plan (exact, `policy_value`) with the gain measured on
n real scenarios, paired with TWAP. z = (predicted − realized) / standard
error, 8 training seeds:

| | n = 100 | n = 400 |
|---|---|---|
| Model right (γ = 0 or 0.005, term learned) | z ∈ [−2.4, +1.2] | z ∈ [−2.5, +1.6] |
| Term missing, γ = 0.005 | **z ∈ [+8.5, +12.9]** | z ∈ [+20.8, +25.5] |
| Term missing, γ = 0.01 | **z ∈ [+20.5, +27.4]** | z ∈ [+45.1, +55.2] |

* **A one-sided threshold z > 4 separates every case:** at n = 100 that's
  24 correct models (also γ = 0 without the term: z ≤ 1.1) and 16 wrong ones.
* **The wrong model is always optimistic.** The planner chooses the actions
  its errors make look best (the optimizer's curse), so "predicted >
  realized" is the signature to test for.
* **Pairing matters:** the unpaired version (predicted vs realized episode
  value) needed ~1,500 episodes to reach z ≈ 5, because episode returns
  have sd ≈ 55 against paired differences of ≈ 10.

### E7d. Unknown unknowns: warm start, fine-tune, guard

When the missing term isn't known, the model can still be useful as a
starting point. The recipe: distill the model's Q-values into TileQ (in the
model's own simulator, so no real episodes are spent), fine-tune on real
rewards with ε 0.1, and guard the deployment with the model's plan as the
baseline. Deployed share, seeds 1–3 (probe `e7_hybrid.cpp`):

| | Start | 2,500 | 5,000 | 10,000 | 20,000 | 40,000 |
|---|---|---|---|---|---|---|
| **γ = 0 (model right, plan 100%)** | | | | | | |
| TileQ from scratch | −3063% | 1–9% | 9–24% | 34–43% | 52–61% | 68–69% |
| Warm start, fine-tuned | 99% | 35–41% | 37–45% | 50–52% | 53–64% | 69–74% |
| Warm start + guard | 99% | 100% | 100% | 100% | 100% | 100% |
| **γ = 0.01 (model wrong, plan 25–28%)** | | | | | | |
| TileQ from scratch | −2286% | −69% to −167% | −24% to −100% | 16–45% | 68–73% | 76–79% |
| Warm start + guard | 25–27% | 27–38% | 27–49% | 48–65% | 69–74% | 78–82% |

* **RL fine-tuning destroys a correct model's policy.** 99% → 35–41% within
  2,500 episodes, and smaller step sizes don't save it (α 0.03: 51%; α
  0.01: 57%). A TD estimate's steady-state jitter is about √(α/2)·σ ≈ 2
  return units (σ ≈ 30), while the action gaps are below 1, so no practical
  step size holds a near-optimal policy against noisy targets. This is E2's
  finding seen from the other side.
* **Warm start + guard is best of both:** 100% when the model is right. When
  it's wrong, the deployed policy is never below the model's plan and ends
  where the model-free learner does (78–82%). Meanwhile TileQ from scratch
  deploys policies far worse than TWAP for its first ~5,000 episodes.
* **The production recipe:** learn a model; check it (`check_model`); if the
  check passes, deploy its plan; if it fails, either expand the model class
  (E7b) or fine-tune a distilled copy under the guard (E7d).

## E8. Online regret: what learning costs while it happens

* **Question:** every experiment so far scored the *deployed* policy, as if
  training were free (a simulator). If every training episode is real, what
  does learning cost compared with just running TWAP?
* **Metric:** cumulative gain over TWAP across all training episodes,
  exploration included, divided by the optimal gain per episode (exact:
  `ExecutionDP::expected_start_value()` − `policy_value(twap)`). The
  optimum would score +N after N episodes. *Break-even* is the episode
  after which the cumulative gain stays positive.
* **Test:** `AgentOnline.LowExplorationCostsLessOnlineAndLearnsAsWell`.
* **Results** (default market, 20,000 real episodes, seeds 1–3; probe
  `e8_regret.cpp`):

| Learner | after 1,000 | 5,000 | 10,000 | 20,000 | Break-even | Final greedy share |
|---|---|---|---|---|---|---|
| TileQ, ε 1 → 0.02 over 10k (as in E0–E7) | −283 to −474 | −1124 to −1504 | −585 to −1027 | +4002 to +4393 | 11.6k–12.8k | 58–61% |
| TileQ, ε 0.3 → 0.02 | −243 to −320 | −73 to +571 | +1353 to +2123 | +6659 to +7379 | 3.1k–5.7k | 56–62% |
| TileQ, ε 0.1 → 0.02 | −190 to +14 | +865 to +1078 | +2497 to +2971 | +7395 to +7652 | 1.5k–2.1k | 60–61% |
| TileQ, ε 0.02 constant | −6 to +14 | +1048 to +1561 | +3085 to +4192 | +7765 to +9918 | 1.0k–1.4k | 56–65% |
| TileQ, greedy (ε 0) | −48 to +52 | +811 to +1954 | +2480 to +4933 | +6968 to +11938 | 0.5k–1.3k | 52–73% |
| ActorCritic | −336 to −408 | −2514 to −4506 | −2629 to +119 | +3769 to +6585 | 9.8k–14.4k | 79–82% |
| Model-based (Shrunk) | +765 to +913 | +4292 to +4826 | +8517 to +9296 | **+17699 to +18902** | 1–42 | 100% |

With permanent impact γ = 0.01 the picture is the same; the model-based
agent *without* the permanent term earns +2326 to +3025 (12–15% of the
optimum online, 19% final), and TileQ with ε 0.1 earns +9551 to +9866.

Final quality at longer horizons (deployed share, seeds 1–3; probe
`e8_long.cpp`):

| Exploration | 10k | 40k | 100k |
|---|---|---|---|
| ε 1 → 0.02 | 32–43% | 65–70% | 72–80% |
| ε 0.1 → 0.02 | 44–52% | 65–70% | 75–77% |
| greedy | 44–67% | 55–81% | 61–85% |

* **Starting ε at 1 is a simulator habit.** Online it costs over a thousand
  optimal-episodes of losses and doesn't break even until ~12,000
  episodes. Starting at 0.1 breaks even 6–8× sooner, earns ~1.8× more over
  20,000 episodes, and learns as well at every horizon.
* **Why so little exploration suffices here:** Q-values start at 0, which
  is optimistic for the bad actions (selling nothing ends in a dump that
  costs up to 500), so greedy selection tries them and learns they're bad.
  Reward noise does the rest.
* **Greedy is a gamble:** cheapest online on average, but its final quality
  depends on luck (61% vs 85% across seeds). ε 0.1 keeps the cost low and
  the outcome predictable.
* **Actor-critic is the costliest online learner** (break-even at
  10k–14k), even though it ends with the best model-free policy. Its
  initial softmax is uniform, i.e. random selling with large dumps.
* **The model-based agent earns 88–95% of the optimal gain while
  learning.** Its 10 random exploration episodes are its only real cost.
  *(Corrected by E11: because of a bug, that phase lasted 20 episodes, and
  the larger cost was the ongoing ε 0.05. With E11's defaults it earns
  95–100%.)*
* **The library default stays ε 1 → 0.02** (A24): sparse-reward tasks
  such as the corridor have no optimistic values to explore with. For
  online learning on cost-like rewards, start at 0.1.

## E9. A changing market: forgetting vs change detection (model-based)

* **Question:** the model-free agent needed 5,000 episodes to get back to
  18% after the signal's meaning flipped (E0b). The model-based agent has
  only ~6 numbers to re-estimate. How fast can it adapt, and at what cost
  when nothing changes?
* **Code:**
  * `ModelBasedExecutionAgent::Config::forget`: per-episode decay of every
    sufficient statistic (exponential forgetting).
  * `detect_drift`, `drift` (`DriftParams`: lag 10, allowance 0.3,
    threshold 10, baseline rate 0.01, warmup 50) and `drift_forget` (0):
    a one-sided CUSUM test on surprise (episode return minus the plan's
    predicted value from the start state). On an alarm the statistics are
    reset and the plan is re-solved after `replan_every` new episodes.
  * `drift_alarms()`. `DriftDetector` moved to `drift.hpp` so both the
    trainer and the model-based agent use it.
* **Tests:** `ModelBased.DetectsAMarketFlipAndRecoversWithinThirtyEpisodes`,
  `ModelBased.ChangeDetectionIsFreeInAStableMarketButConstantForgettingIsNot`.
* **Setup:** 300 episodes with alpha = +1, then alpha = −1; replanning
  every 5 episodes. Share of the new regime's optimum (seeds 1–3; probes
  `e9_probe.cpp`, `e9b_probe.cpp`):

| Variant | +10 | +20 | +50 | +100 | +300 | Online gain over the 300 episodes after the flip (of 300) |
|---|---|---|---|---|---|---|
| No forgetting | −169% to −171% | −165% to −167% | −154% to −159% | −123% to −129% | 80–82% | −186 to −237 |
| Forget 0.99 (half-life ~70) | −160% to −162% | −142% to −146% | 0–5% | 94–97% | 99–100% | +114 to +200 |
| Forget 0.95 (half-life ~14) | −35% to −115% | 79–100% | 99% | 100% | 98–100% | +204 to +290 |
| **Detect + reset** | −169% to −171% | **95–100%** | 99–100% | 99–100% | 99–100% | +178 to +292 |

Alarms fired 7–13 episodes after the flip. In stable markets (3,000
episodes, seeds 1–3; share of the optimum at the end):

| Market | No forgetting | Forget 0.99 | Forget 0.95 | Detect + reset |
|---|---|---|---|---|
| default | 100.0–100.1% | 99.9–100.2% | 97.5–99.4% | 100.1–100.2% (1 false alarm in 9,000 episodes) |
| noise 0.2 | 99.8–100.2% | 98.1–99.9% | **54.4–93.0%** | 99.9–100.2% (2 in 9,000) |
| q³ impact + fixed cost | 99.8–100.0% | 96.6–97.4% | 89.9–93.0% | 99.8–100.0% (0) |

* **A model that never forgets is slow to adapt:** its estimates average
  both regimes, so alpha only changes sign after as many new episodes as
  old ones (−123% after 100 episodes).
* **Constant forgetting trades accuracy for tracking.** At 0.95 it recovers
  in ~20 episodes but always plans on ~20 episodes' worth of data, which
  costs up to 46 points in a noisy market. With 0.99 the cost is small but
  recovery takes ~100 episodes.
* **Change detection gives both:** full memory while the market is stable,
  a reset when it isn't. It recovered to 95–100% within 20 episodes, 250×
  faster than the model-free agent reached 18%, because a handful of
  parameters re-estimate from a few episodes while tile weights need
  thousands of noisy updates. A false alarm costs little: the agent
  relearns a stable market in ~20 episodes.

## E13. Regime switches on the second task: when the market gets *better*

* **Question:** do drift detection and the policy bank (E0b, E3) carry over
  to market making unchanged?
* **First attempt, a null result:** doubling volatility doesn't change the
  optimal quotes at this action granularity (each regime's optimum scores
  100% in the other), so there's nothing to adapt to. The regimes used
  instead differ in book depth: fill decay 1 (A) vs 0.3 (B, deep book).
  A's optimum gets 66% of B's optimal gain; B's gets 79% of A's.
* **What went wrong, and why:** switching to B was never detected, so the
  agent sat at 66% of the new optimum for 1,000+ episodes. Two causes:
  1. **An improvement isn't a "drop".** In the deep book *every* policy
     earns more (A's optimal policy: 27.4 → 63.8 per episode), and the CUSUM
     test only looked for falling returns.
  2. **Blindness after rejected alarms (a bug).** Every alarm, including
     one the champion re-score rejected, reset the detector, which then
     needed lag + warmup = 1,550 samples before it could fire again. A false
     alarm at episode 9,030 left it blind until ~10,580; the switch came at
     10,000. When it finally fired (at +1,337), the champion had already been
     re-scored in the new world at regular evaluations, so confirmation saw
     "no change" and rejected it too.
* **Fixes:**
  * `DriftParams::two_sided` (off by default): a mirror-image CUSUM flags
    sustained *rises* in surprise; confirmation then accepts a significant
    rise as well as a drop.
  * **Evaluation-time detection (always on with `detect_drift`):** at every
    evaluation the champion's re-score is compared with its previous score.
    The champion is frozen and the scenarios are fixed, so in an unchanged
    world the two are identical; a shift of more than 2 standard errors is
    a confirmed change in either direction, with latency ≤ `eval_every` and
    no false alarms. The old champion is kept for that evaluation so it can
    be banked. `EvalPoint::world_changed` records it.
  * **No blindness:** an alarm now only clears the accumulated evidence. The
    caller resets the baseline after a confirmed change, and calls
    `rebase()` after a false one, which re-centres on recent samples and
    stays armed (0–1 false alarms in 300 samples after a rebase, real changes
    caught within 1–3 samples; 10 seeds).
* **Tests:** `AgentDrift.RebaseAfterAFalseAlarmStaysArmed`,
  `MarketMaking.AnImprovedMarketIsNoticedAndAReturningOneRecalled`.
* **Results** (actor-critic, 10k episodes in A, then B/A/B/A every 5,000;
  deployed share of the current regime's optimum, seeds 1–3; probe
  `e13_probe.cpp`):

| Switch | Detection | One-sided + eval-time, bank on: +200 / +1,000 / +5,000 | Two-sided, bank on | One-sided, bank off |
|---|---|---|---|---|
| → B (first) | one-sided: +500 (evaluation); two-sided: +4–5 | 66–68 / 66–69 / 87–90% | 66–68 / 74–76 / 87–91% | as bank on |
| → A | +4–6 (CUSUM) | **99–100** / 100 / 99–100% (recalled) | 99–100 / 100 / 100% (recalled) | 89–90 / 89–90 / 89–90% |
| → B | one-sided +500; two-sided +4–8 | 65–68 / 88–90 / 89–92% (recalled at +500) | **87–91** / 87–91 / 88–93% (recalled) | 87–90% throughout |
| → A | +3–5 | 99–100 / 100 / 100% (recalled) | 99–100 / 100 / 100% (recalled) | 88–90% throughout |

* **A changed world can be good news,** and an agent that only watches for
  bad news misses it. The cheapest reliable detector here is the one the
  trainer already had: the champion's exactly reproducible held-out score.
* **The bank does the heavy lifting on returns:** with it, every return to
  A is back at 99–100% within 200 episodes; without it actor-critic stays
  at 88–90%.
* **Actor-critic re-exploration, a mixed result** (`ac_reexplore_temperature`,
  default off). Re-exploring with ε-uniform actions is off-policy for the
  actor's update: on market making, without the bank, it stalled at 88–92%
  even 10,000 episodes after a switch. Sampling the policy itself at triple
  temperature, decaying with the boost, reached 95–99%. On execution's
  signal flip, though, where the old policy is actively harmful (−140%),
  the flattened softmax didn't explore enough: 29–30% at +40,000 against
  37–52% for ε-uniform (probe `e13d_exec.cpp`). Neither is the default for
  every task; ε-uniform stays the default.

## E14. Tail risk: what the mean doesn't show

* **Question:** every score so far is a mean. How do the policies' bad days
  compare, and does a variance penalty protect against them?
* **Code:** `episode_returns()` (per-episode returns on the usual scenarios)
  and `cvar(returns, alpha)` (mean of the worst `alpha` fraction) in
  `evaluate.hpp`.
* **Tests:** `TailRisk.CvarArithmetic`,
  `TailRisk.VarianceIsNotTailRiskInExecution`,
  `MarketMaking.TheInventoryPenaltyCutsTheTail`.

  the risk penalty switched off), on 20,000 shared scenarios (probe
  `e14_probe.cpp`).

Execution:

| Policy | Mean | sd | CVaR 5% | CVaR 1% | Worst |
|---|---|---|---|---|---|
| TWAP | −5.6 | 54.5 | −117.1 | −150.8 | −215.4 |
| DP optimum, λ 0 (risk-neutral) | +10.0 | 57.4 | −66.0 | −78.1 | −118.1 |
| DP optimum, λ 0.05 | +9.2 | 52.6 | −62.5 | −76.6 | −117.5 |

| DP optimum, λ 1 | −8.2 | 27.5 | −61.1 | −75.7 | −116.6 |
| TileQ, 40k episodes | +5.1 | 51.1 | −72.7 | −90.8 | −135.2 |
| ActorCritic, 40k episodes | +7.2 | 52.3 | −64.9 | −77.2 | −116.4 |

Market making (default risk penalty 0.05 unless noted):

| Policy | Mean | sd | CVaR 5% | CVaR 1% | Worst |
|---|---|---|---|---|---|
| Symmetric quotes | +22.9 | 26.3 | −47.7 | −79.7 | −145.4 |

* **Volatility isn't tail risk.** The risk-neutral execution optimum is
  *more* volatile than TWAP (sd 57 vs 54) yet loses far less on its worst
  days (CVaR 5% −66 vs −117): the signal lets it avoid the worst outcomes,
  and the extra spread is on the upside.

  λ = 1 halves the sd (57 → 28) but improves the worst 5% only from −66 to

  tasks; TileQ's execution policy has a noticeably worse tail (−73 vs −66)
  than its mean gap suggests.
* **Practical rule:** check the tail you care about directly (CVaR on cash
  outcomes); whether a variance penalty helps depends on where the tail
  comes from.

## E15. A model-based market maker

* **Question:** on execution, learning a model beat model-free learning by
  orders of magnitude (E1). Market making is the *easy* task for model-free
  learners (E12). Does a model still pay?
* **Code** (`market_making.hpp`):
  * `MarketMakingParams::fill_probs`: an optional fill probability per quote
    distance, so a market can have a fill curve that isn't exponential.
  * `MarketMakingEnv::last_bought()`, `last_sold()`, `last_mid_move()`: the
    agent's own fills and the mid move, which a real market maker sees as
    execution reports and market data.
  * `ModelBasedMarketMaker`: knows its objective (risk penalty, liquidation
    penalty, inventory cap, distances) but not the market. It estimates each
    distance's fill probability by counting (Beta(1, 1) prior, pooling bid
    and ask) and the volatility from observed moves, then plans with
    `MarketMakingDP`. The fill model is non-parametric over the three
    distances. Three random episodes first, then ε 0.01; re-plans after 5
    episodes, doubling. `train_model_based()` runs it online.
* **Test:** `MarketMaking.AModelBasedMarketMakerNeedsAFewEpisodes`.
* **Results** (seeds 1–3; probe `e15_probe.cpp`):

| Fill curve (distances 0.5 / 1 / 2) | Model-based after 3 / 10 / 50 episodes | Online gain over 1,000 episodes (of 1,000) | ActorCritic after 1,000 | ActorCritic online |
|---|---|---|---|---|
| exponential (0.55 / 0.33 / 0.12) | 100 / 100 / 99–100% | +986 to +1,009 | 94–96% | +655 to +678 |
| steep (0.85 / 0.15 / 0.10) | 98–100 / 98–99 / 99–100% | +989 to +995 | 99–100% | +770 to +788 |

  After 1,000 episodes the estimated fill probabilities match the truth to
  two decimals (one is 0.17 for 0.15) and the volatility to 1.00.

* **A model pays even on the easy task:** 3 episodes instead of 5,000, and
  99–100% of the optimal gain earned *while* learning instead of 65–79%.
* **Why it's so fast here:** the unknowns are four numbers, each observed
  directly (fills are counted, moves are seen), and the planner is exact.
  The expensive part of model-based RL is getting the model *class* right;
  here it's non-parametric over the three distances, so any fill curve fits.

## E16. A neural Q-learner, from scratch

* **Question:** you asked whether a framework like PyTorch would do better.
  Rather than add the dependency, the question behind it was tested with a
  small neural network written from scratch: does neural function
  approximation beat tile coding on execution, and if so, why?
* **Code:**
  * `mlp.hpp`: a multilayer perceptron (ReLU hidden layers, linear output),
    backpropagation, Adam and plain SGD, He-uniform initialization from the
    seeded `Rng`. No library.
  * `LearnerKind::NeuralQ` in `agent.hpp`: DQN-style. The MLP (default 2 ×
    64 hidden units) maps the features to five Q-values; each finished
    episode becomes 3-step transitions in a feature-space replay buffer
    (100k); one Adam minibatch (32) per step taken; a target network copied
    every 2,000 updates. `AgentConfig::nn_hidden`, `nn_lr`, `nn_batch`,
    `nn_target_sync`, `nn_warmup`. Trainer, champion, drift detection and
    guard work unchanged.
* **Tests:** `Mlp.GradientMatchesFiniteDifferences`,
  `Mlp.AdamFitsASmoothFunctionAndIsDeterministic`,
  `AgentNeural.LearnsFasterThanTileCodingOnExecution`,
  `AgentNeural.EvaluationDoesNotPerturbLearningAndSnapshotsAct`.
* **Verification:** backpropagation matches finite differences to
  1.4 × 10⁻¹¹; the network fits a nonlinear 3-D function to MSE 0.0004.

**Representation** (supervised fit to the exact Q*, greedy policy; probe
`e16_dqn.cpp fit`, `ceiling2.cpp`):

| Function approximator | Weights | Greedy on fitted Q* |
|---|---|---|
| MLP 3-32-32-5 | 1,349 | 83.6% (one step per episode) |
| MLP 3-64-64-5 | 4,741 | 92.8% (one step per episode); **98.6%** (one per state) |
| MLP 3-128-128-5 | 17,669 | 99.0% |
| tiles 8×8×8 × 8 (default) | 5,832 per action | 99.4% |
| tiles 4×4×4 × 8 | 1,000 per action | 98.2% |
| tiles 2×4×4 × 16 | 1,200 per action | 98.3% |

All of them can represent a ≥ 98% policy. The differences below are about
learning, not capacity.

**Learning from rewards** (default market, ε 1 → 0.02 over 10k episodes,
greedy learner's share of the optimal gain, seeds 1–3; probes
`e16_dqn.cpp`, `e16_tileq.cpp`, `e16_coarse.cpp`):

| Learner | 3,000 | 5,000 | 20,000 | 40,000 |
|---|---|---|---|---|
| TileQ, default tiles, 4 replays/step | −13 to +19% | 8–16% | 56–60% | 65–69% |
| TileQ, default tiles, 32 replays/step | −72 to −5% | 2–21% | 48–57% | 58–61% |
| TileQ, tiles 4×4×4 × 8 | | 7–46% | 57–67% | 72–75% |
| TileQ, tiles 2×4×4 × 16 | | 33–47% | 65–72% | **76–77%** |
| **DQN (MLP 64-64, Adam, target net)** | 67% (seed 1) | 66–81% | 76–86% | **84–89%** |

Ablations (DQN, 20,000 episodes, seeds 1–2):

| Variant | 5,000 | 10,000 | 20,000 |
|---|---|---|---|
| as above | 66–81% | 68–82% | 76–86% |
| no target network | 57–73% | 78–81% | 85–87% |
| SGD lr 10⁻³ instead of Adam | 63–75% | 78–80% | 67–83% |
| SGD lr 10⁻² | diverged | | |

* **The neural learner breaks the plateau:** 84–89% at 40k episodes
  against 65–69% for tile-coded Q-learning (and 75–77% after 200k, E2),
  with the same 3-step targets and the same exploration schedule.
* **It isn't the extra computation:** giving TileQ 32 replayed updates per
  step (DQN's minibatch) made it *worse* (58–61%).
* **It isn't the target network or Adam:** without the target network it
  did as well (85–87% at 20k); plain SGD reached 67–83% (less stable, but
  far above TileQ).
* **It's how the function generalizes.** Coarser tiles, which average the
  noisy targets over more states per weight, already lift TileQ from
  65–69% to 76–77% while keeping a 98% representation ceiling, so the
  default 8×8×8 tiling is too fine for this noise level (A3 concluded the
  same about 12³ vs 8³). The network goes further: it averages globally
  but can still put resolution where the values bend.
* **Through the library** (`LearnerKind::NeuralQ` with the standard
  `Trainer`, champion evaluated every 1,000 episodes on 500 scenarios,
  seeds 1–3; probe `e16_lib.cpp`): deployed 63–80% at 5k, 78–87% at 10k,
  81–88% at 20k, **86–92%** at 40k.
* **The champion matters more for neural learners:** the learner's greedy
  policy swings between checkpoints (seed 1: 81% → 70% → 90%; seed 2 ends
  at 73%), while the deployed champion holds (87%, 86%).
* **Costs:** about 7.5 ms of training per episode (vs ~0.1 ms for TileQ)
  and 1.7 µs per greedy decision (vs 39 ns), measured with the current
  scalar double-precision forward pass (not yet vectorized). For a latency-critical deployment the
  natural split is to train the network offline and distill it into tiles
  or a lookup table.
* **What this changes in the earlier conclusions:** E2 was right that the
  tiles could represent a near-optimal policy and that target noise was the
  problem, but wrong to imply that the representation choice didn't matter.
  How a function approximator *averages* noise is as important as what it
  can represent.

| noise_sd 0.2 | −1–10% / 49–61% | **21–26% / 67–71%** |

* **In the default market it does nothing,** because the innovation is not
  the dominant noise. Most of the return's variance comes from the signal
  path (sd 53–56): the very information the agent trades on, realized along
  a random path. A reward-side control variate can't remove that without
  changing the optimal policy.
* **Where the innovation is large, it works exactly as theory says:** with
  noise_sd 0.2 it lifts TileQ from 49–61% to 67–71%, the level of the
  default market.
* **Lesson:** decompose the return variance before reducing it. The
  research's prediction ("the largest single gain; above 90%") assumed the
  innovation dominated; measured, it was 5% of the variance.

## E19. Advantage learning: widening the action gaps

* **Question:** RESEARCH.md §2 suggests gap-increasing targets for tasks
  whose action-value gaps are tiny relative to target noise (here: gaps < 1,

  subtracts k × (max_b Q(s, b) − Q(s, a)) from each target, which widens
  the gaps while preserving the optimal policy.
* **Code:** `AgentConfig::advantage_learning` (k; default 0 = plain
  Q-learning), applied in TileQ's TD update.

## RAG engine

| # | Decision | Why (evidence) |
|---|---|---|
| R1 | Hybrid retrieval: dense + BM25, fused by RRF (k0 = 60) | Rank fusion needs no score calibration between cosine and BM25. Exact identifiers (e.g. "ZX81Q") are found by BM25 even when embeddings blur them. |
| R2 | Zero allocation on the query path, with per-thread `QueryContext` scratch | Allocation is a source of latency spikes; enforced by a test counter. |
| R3 | `dense_min_score = 0` (strict) | **Bug found by coverage review:** stopword-only chunks have all-zero embeddings, scored 0, and still entered prompts. |
| R4 | int8 rows with fp32 rerank of 128 | Scans are DRAM-bound (~10 GB/s); int8 moves 4× fewer bytes: 15.4 ms → 2.95 ms on 100k rows, recall ≥ 0.95 in tests. |
| R5 | IVF-SQ8 (int8 inverted lists + fp32 rerank) | p99 1.08 → 0.43 ms at 60k chunks against fp32 IVF. |
| R6 | Batched queries, 8 per memory pass | Exact 84 → 460 queries/s. Bit-exactness needed `simd::dot1` (one `dot4` lane), because `dot()`'s 4-accumulator summation order differs. |
| R7 | `commit()` concurrent with queries via immutable snapshots + epoch-based reclamation | Readers pin with one store to their own cache line. A mutant that frees without EBR is caught by `rag_stress` under ASan within seconds. |
| R8 | Storage allocated lazily, query scratch pre-faulted | Huge-page first touch was 11× slower (1.17 s per 200 MB). Writer-filled storage never faults on readers. Load dropped from 5.7 s to < 1 s. |
| R9 | Index file: checksum plus structural validation of every field | **Bug found while testing:** `offset + len > total` overflowed, so a forged file could point a chunk out of bounds; checksums don't stop forgers. |
| R10 | Saves use a tmp file, fsync, rename, then fsync the directory | Rename alone is atomic but not durable after power loss. |
| R11 | Saved snapshot reused on load when the parameters match | IVF training dominated load time (4.2 s). |
| R12 | Arena bounds checked on integer addresses | **Bug found by fuzzing:** `nullptr + n` on a fresh arena. GCC's UBSan misses it, so CI also runs Clang's. |

| R13 | `EngineConfig` validation rejects BM25 `k1 < 0` or non-finite, and `b` outside [0, 1] | **Bug found by the RAG review agent:** `k1 = -1` made every posting weight 0 and the next query overflowed a heap buffer in `Bm25Index::search`. |
| R14 | `Bm25Index::load()` rejects posting weights that aren't finite and > 0 | **Bug:** a forged file with a valid checksum and zero weights loaded, then overflowed at query time (checksums don't stop forgers; R9). |
| R15 | IVF scores every list row with `simd::dot1` | **Bug:** the tail of each list used `dot`, so a row's score depended on its position: 46 of 1,280 hits differed from the exact scan with every list probed. Same root cause as R6. |
| R16 | IVF training samples at least one point per list; `build(store, 0)` resets the whole index | **Bugs:** `max_train_points_per_list = 0` divided by zero (SIGFPE) on the first IVF commit; rebuilding a used index over zero rows let `save()` write a file its own `load()` rejects. |

# Conventions and working rules

These are the rules the codebase has followed so far. Following them keeps
every claim in the docs measurable and every change verifiable.

## Code

* **Language:** C++20, header-only, `#pragma once`, namespace `rag` (agent:
  `rag::agent`).
* **Hot paths** (query, `act()`) don't allocate. Use fixed `std::array`
  scratch, `TopK<Cap>` on the stack, and per-thread contexts. Tests enforce
  this with the global `operator new` counter (`begin_alloc_count()` /
  `end_alloc_count()` in `tests/test_util.hpp`).
* **Cold paths** (ingest, commit, load, training setup) may allocate, and
  should allocate once.
* **Warnings:** builds use `-Wall -Wextra -Wpedantic -Wconversion` with
  `-Werror` in CI. Silence a narrowing conversion with an explicit
  `static_cast`, not a pragma.
* **Bounds checks** are written so they can't overflow, e.g.
  `len > total || off > total - len`, never `off + len > total`.
* **Untrusted input** (index files, PDFs, query text): validate everything
  before use and before mutating any state. Error messages name the failed
  check; tests match on them.
* **SIMD:** dispatch at compile time (`__AVX512F__`, `__AVX2__`, scalar
  fallback). Any score that must equal a `dot4` lane uses `simd::dot1`.
* **Determinism:** seeded `rag::agent::Rng` everywhere (no `std::mt19937`).
  Greedy evaluation must not consume the agent's RNG.
* **Comments** explain why, and quote measurements where a choice was made
  on evidence.

## Tests

* Every bug fix gets a regression test, and the test is shown to fail on the
  old code (mutation check) before it's trusted.
* Prefer exact checks (accounting identities, bit-exact equality, brute-force
  references) over loose ones.
* Statistical claims use paired comparisons on common random numbers, with
  thresholds set below the range measured across seeds and the measurement
  quoted in a comment.
* **Test files:**
  * `rag_tests.cpp`: engine;
  * `forgery_tests.cpp`: loader checks (add a case for every new file field);
  * `reference_tests.cpp`: spec-level reference;
  * `agent_tests.cpp`: agent;
  * `api_examples_tests.cpp`: the snippets in `docs/ai/API.md`.

## Verifying a change (what "done" means here)

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j && ctest --test-dir build -j4
```

1. **Before pushing**, run the same 7 jobs as CI: gcc native, AVX2
   (`-DRAG_ARCH=x86-64-v3`) and scalar (`-DRAG_ARCH=x86-64`); clang; ASan+UBSan
   with both gcc and clang (`-DRAG_SANITIZE=ON`); and TSan (`-DRAG_TSAN=ON`).
   All use `-DCMAKE_CXX_FLAGS=-Werror`.
2. **For loader or parser changes**, fuzz:
   `-DRAG_FUZZ=ON -DCMAKE_CXX_COMPILER=clang++`, `make_seeds`, then run

3. **For performance claims**, use `rag_bench` / `rag_latency`, and update
   `README.md` and `bench_results.txt` from the same run.

## Git

* Work on a branch. Push, wait for the 8 GitHub CI jobs, then fast-forward
  `main` to the green commit.
* Commit messages explain what changed and why, with measured results.

## Documentation

* Numbers in docs come from a recorded run (benchmark output, demo output,
  test thresholds). Re-measure rather than copy when the code changes.
* Experiments go in `docs/ai/EXPERIMENTS.md`, including the ones that

## Works and is verified

* **RAG engine:**
  * hybrid retrieval in four dense modes;
  * zero-allocation queries;
  * batched queries, bit-identical to single queries;

    episodic memory;
  * a model-based agent (grey-box regression plus DP planning) at 99–100%
    of the optimum after 20–50 episodes;
  * an exact DP yardstick, also for generalized cost tables;
  * held-out evaluation and champion/challenger deployment;
  * two-stage drift detection with re-exploration, plus a change check at
    every evaluation that also catches markets that got better;
  * a policy bank that recognizes returning regimes;
  * an actor-critic learner (the best model-free one here) and risk-averse
    (mean-variance) objectives with an exact optimum;
  * an optional baseline guard: never deploy a policy that hasn't beaten
    TWAP;
  * a paired model check that flags a wrong model after 100 episodes, and
    warm-starting a model-free learner from a model's plan;
  * change detection for the model-based agent: recovery within 20
    episodes of a market flip, free while the market is stable;
  * off-policy evaluation (importance sampling, doubly robust, ESS
    diagnostics) and exact policy evaluation under a model;
  * a second task (market making, exact DP) on which the unchanged agent
    learns the optimal inventory skew, and a model-based market maker;
  * a from-scratch neural Q-learner (`NeuralQ`, no ML library) that breaks
    the tile-coding plateau on execution (91.5% [90.1, 92.7] at 40k
    episodes with Double DQN, 8 seeds; E21 ranks every learner);
  * optional NLopt/Eigen tooling: hyperparameter search validated on
    held-out seeds, sensitivity analysis, rank-revealing least squares.
* **Reviews:** three review agents (adversarial bug hunt, coverage, RAG
  property tests) found and fixed 14 bugs, six of them in the engine
  (including a heap overflow reachable through config and through a forged
  index file, R13–R17); agent-header coverage is 99.7% of lines and 99.0% of
  regions. Their schedule fixes may shift the online-gain numbers of E8,
  E11 and E15 slightly; those were measured before the fixes.
* **Testing:**
  * the CI matrix covers SIMD levels, sanitizers and fuzzing;
  * 287 ctest cases: 272 in `rag_tests`, 4 in `rag_optlib_tests`, 9 PDF tests (Poppler), the
    stress run and a `rag_pdf` CLI smoke test.
  * The TSan CI job skips the single-threaded learning suites (`Agent*`,
    `ModelBased`, `ExecutionCosts`, `OffPolicy`, `MarketMaking`, `Reference`, `ApiExamples`), which ran
    for over an hour under TSan and have no threads to check.

## Known limitations

* **No neural embedder.** `HashingEmbedder` is lexical-ish (feature-hashed
  unigrams and bigrams). The `Embedder` concept is ready for ONNX or
  llama.cpp encoders, but none could be fetched or tested here (Hugging Face
  is blocked by this environment's network policy).
* **No LLM call.** The engine produces prompts; `Generator` is a concept
  only.
* **`commit()` rebuilds BM25 (and IVF) from scratch:** O(total corpus) per
  commit. Incremental segments would be the scalable design.
* **Capacity is fixed** at construction (`max_chunks`), and there are no
  deletes or updates of chunks.
* **PDF scope:** no OCR for scanned pages, and encrypted PDFs are rejected.
* **Agent:**

    relative to the gain (0.27 return-sds per episode): default TileQ

  * `ExecutionEnv` and `MarketMakingEnv` are stylized on purpose (exact DP
    optima): no order-book dynamics, queue position or real data;
  * `NeuralQ` is CPU-only and unvectorized (1.7 µs per decision).
* **Optional tooling:** tuning and analysis need NLopt and Eigen
  (`RAG_OPTLIBS`); without them those targets are skipped.
* **Machine-specific numbers:** benchmarks come from one shared 4-vCPU VM.

## Open questions and suspicions (from the review agents, not confirmed as bugs)

* `simd::quantize_i8`: a vector whose largest component is below ~3.7e-37
  overflows the scale (unreachable for unit-norm embeddings).
* `IvfIndex::load` checks row ids are in range but not unique; a forged
  file can repeat ids (duplicate hits, no memory-safety issue).
* IVF-SQ8 reranks committed rows with `simd::dot` but uncommitted rows with
  `dot1`: a row can score an ulp differently before and after `commit()`.
* `RrfParams` and `CleanOptions::repeated_line_fraction` aren't validated
  (NaN or negative values lead to an undefined float-to-int cast).
* `DriftDetector::rebase()` counts the held samples twice in the new
  baseline (slower adaptation, no failing scenario found).
* With `keep_champion = false`, the baseline guard checks the champion but
  deploys the learner.
* `MarketMakingEnv::reset()` doesn't clear `last_bought`/`last_sold`/
  `last_mid_move`; `ExecutionEnv::features` divides by `signal_sd`.
* The online-gain numbers of E8, E11 and E15 were measured before the
  re-plan schedule fix (A40) and may shift slightly.

## Next steps (in rough priority order)

1. A neural `Embedder` (e.g. ONNX Runtime with a MiniLM model, 384 dims to
   match), on a machine that can download models.
2. Incremental BM25 segments with background merging.
3. Agent: vectorize `NeuralQ`'s forward pass (float, SIMD) and distill a

4. Agent: the research's remaining ideas (RESEARCH.md §5): all-action

5. Tune `NeuralQ` and actor-critic with `tune_agent`'s machinery (needs a
   larger compute budget: one NeuralQ evaluation is ~75 s per seed).
6. A richer market simulator (queue position, order book) for both tasks.
7. Resolve the open questions above.

# rag-cpp — header-only, low-latency Retrieval-Augmented Generation in C++20

[![CI](https://github.com/Rcoding123/rag-cpp/actions/workflows/ci.yml/badge.svg)](https://github.com/Rcoding123/rag-cpp/actions/workflows/ci.yml)

Hybrid retrieval (dense ANN + BM25, fused by RRF) with a zero-allocation query
path, SIMD similarity kernels (AVX-512 VNNI / AVX2 / scalar), and lock-free
single-writer / multi-reader ingestion.

```
INGEST (1 writer)                                   QUERY (N readers, 0 allocations)
text ─► Arena (stable string_views)                 query ─► tokenize   (stack, constexpr LUT)
     ─► tokenize ─► sliding-window chunks                 ─► embed      (stack, L1)
     ─► Embedder ─► VectorStore.append ─┐                 ├─► dense:  Exact | Int8+rerank | IVF | IVF-SQ8, + delta scan
     ─► Bm25Builder.add                 │                 └─► BM25:   impact-scored postings, dense accumulator
commit() ─► Snapshot ─► atomic swap     │                      ─► RRF fusion (stack)
                                        │                      ─► prompt into preallocated buffer ─► Generator
        size.store(n+1, release) ───────┴──► size.load(acquire): new chunks searchable immediately (dense)
```

| Header | Role | Key latency technique |
|---|---|---|
| `common.hpp` | aligned buffers | 64 B / 2 MiB alignment, `MADV_HUGEPAGE`; query scratch pre-faulted, storage faulted by the writer |
| `arena.hpp` | document text | bump-pointer, blocks never move → lock-free readers |
| `tokenizer.hpp` | terms | constexpr 256-byte class/lowercase LUT, constexpr FNV-1a, compile-time stopword table |
| `chunker.hpp` | chunking | zero-copy byte ranges, token-window with overlap |
| `embedder.hpp` | `Embedder` concept + hashing embedder | signed feature hashing, Lemire fast-range (no division) |
| `simd.hpp` | kernels | 4-accumulator FMA, 4-row register blocking, int8 sign-trick / VNNI `vpdpbusd` |
| `topk.hpp` | selection | stack `std::array` heap, cached threshold, `[[likely]]` reject |
| `vector_store.hpp` | dense storage | SoA fp32 + int8 + scale, SWMR via release/acquire, padded atomic |
| `ivf_index.hpp` | ANN | spherical k-means, CSR lists of contiguous reordered vectors, fp32 or int8 (SQ8) storage |
| `bm25.hpp` | lexical | precomputed per-posting BM25 impact, open-addressing dictionary, touched-list reset |
| `fusion.hpp` | RRF | linear id-match over stack array (K ≤ 64) |
| `prompt.hpp` | context assembly | fixed buffer, reserved question space, greedy token-budget packing |
| `epoch.hpp` | snapshot reclamation | per-reader padded epoch slots, seq_cst publish/scan |
| `text_clean.hpp` | page text cleanup | ligatures, dehyphenation, running header/footer removal, paragraph reflow |

## Batched queries

```cpp
std::vector<Engine::QueryContext> ctxs;  // one per in-flight query
for (int i = 0; i < 8; ++i) ctxs.push_back(engine.make_context());
std::array<Engine::QueryResult, 8> out;
engine.query_batch(queries, /*k=*/8, ctxs, out);
```

In `Exact` and `Int8Rerank` modes, each group of up to 8 queries shares
**one** pass over the vector matrix. Those scans are limited by DRAM
bandwidth, so each row is loaded once and then scored against all 8 queries
from L1. The fp32 kernel runs a register-blocked tile of 1 row by 4 queries,
reusing `dot4`.

Batch results are **bit-identical** to calling `query()` on each query,
because the batch and single-query kernels add up each row's products in the
same order (`simd::dot1` matches each `dot4` lane). IVF modes probe different
lists for each query, so they run one query at a time inside a batch.

End-to-end, 60k chunks, one core (`Pipeline/query*` in `bench_results.txt`):

| mode | one at a time | batches of 8 | gain |
|---|---|---|---|
| exact | 84 queries/s | 460 queries/s | 5.5x |
| int8 + rerank | 428 queries/s | 890 queries/s | 2.1x |

Batching trades latency for throughput: each query in a batch waits for the
whole batch (17.4 ms per batch of 8 in exact mode, against 11.9 ms for one
query). Use it when many queries arrive together, for offline evaluation, or
when throughput matters more than latency.

## Persistence

```cpp
engine.save("corpus.ragidx");                                    // writer thread; queries keep running
auto engine2 = RagEngine<HashingEmbedder<384>>::load("corpus.ragidx", cfg);
```

* **What's in the file:**
  * chunk text and metadata;
  * fp32 vectors;
  * BM25 builder state, so ingestion can continue after load;
  * the committed snapshot (frozen BM25 plus IVF), with the parameters it
    was built with.
* **Index reuse:** `load()` reuses the saved snapshot when the new config
  asks for the same BM25 and IVF parameters and the snapshot covers every
  chunk. Otherwise it rebuilds, and the results are identical either way.
  Pass a `LoadReport*` to see which path it took.
* **Safety:**
  * The trailing checksum catches corruption.
  * Every offset and ID is checked against the structure it indexes, so a
    file with a valid checksum but forged contents still can't cause an
    out-of-bounds read.
  * Array lengths are checked against the bytes left in the file before
    anything is allocated.
  * The file records the embedder's identity (`E::kName` and the dimension),
    so loading vectors made by a different model fails instead of returning
    wrong results.
* **Crash-safety:** a save writes `<path>.tmp`, fsyncs it, renames it over
  `<path>`, and fsyncs the directory. After a crash, `<path>` holds either the
  old index or the new one, never a partial file.

Measured on the 60k-chunk benchmark corpus (file about 276 MB with int8 IVF lists):

| | exact | ivf-sq8 |
|---|---|---|
| build from text (tokenize, embed, index) | 2.9 s | 5.6 s |
| save | 1.6 s | 1.9 s |
| load (indexes reused) | 0.65 s | 0.97 s |

With the built-in hashing embedder, building from text is cheap. With a
neural encoder, embedding dominates the build, so loading instead can save
minutes or hours.

## Thread-safety contract

* **Writer side:** `ingest()` and `commit()` run on one thread at a time.
* **Readers:** `query()` runs on any number of threads, concurrently with both
  `ingest()` and `commit()`. Each thread owns a `QueryContext`, up to 128 live
  at once.
* **How `commit()` stays safe:**
  1. It builds a new immutable `Snapshot` (BM25 plus IVF) while queries keep
     running.
  2. It publishes the snapshot with one atomic exchange.
  3. It retires the old snapshot through epoch-based reclamation
     (`epoch.hpp`). Each query pins a snapshot by writing to its own
     cache-line slot, so pinning costs no read-modify-write and no shared-line
     write.
* **Consistent reads:** `engine.pin(ctx)` holds one snapshot across several
  reads. Each `QueryResult` reports the `snapshot_version` it was served from.
* **Lifetime:** destroy every `QueryContext` before the engine.

## Testing

| Layer | What it checks |
|---|---|
| `tests/rag_tests.cpp` | Unit and integration tests per component. Includes SIMD kernels against scalar references (bit-exact for int8) and recall floors for every approximate mode. A global `operator new` counter proves the query paths make zero heap allocations. |
| `tests/reference_tests.cpp` | Differential tests against a deliberately naive reference written from each stage's spec (`std::string`, `std::map`, `double`). Covers tokenizer, chunker, stopwords, embedder, BM25, exact dense ranking and RRF on randomized corpora and configs. |
| `tests/forgery_tests.cpp` | Every structural check in the index loader, using files with a **valid** checksum and one forged field each. Each case requires its check's specific error message. |
| `tests/fuzz/` | libFuzzer targets (`-DRAG_FUZZ=ON`, Clang). `fuzz_load` loads arbitrary payloads with a fixed-up checksum, then queries, ingests, commits and reloads them. `fuzz_text` checks tokenizer, chunker, engine and prompt invariants on arbitrary bytes. |
| `tests/stress.cpp` | `rag_stress <seconds>`: one writer ingests, commits, saves and reloads while threads run single queries, batches and long pins. Committed documents must rank first for their unique token, batch and single results must agree on the same snapshot, pinned snapshots must never change, and everything retired must be reclaimed. |

What this found:
* **Integer overflow in `load()`:** the chunk-text bounds check could wrap
  around and let a forged file point a chunk outside its buffer. Found by
  coverage review and the forgery tests.
* **Arena UB:** a fresh arena's first allocation computed `nullptr + n`.
  Found by the fuzzer; GCC's UBSan misses this, so CI now also runs Clang's.
* **Irrelevant dense hits:** chunks with zero or negative similarity (for
  example, stopword-only chunks) filled the dense list and reached prompts.
  Hence `dense_min_score`.

Checking the checks:
* **Mutation testing:** eight planted bugs (BM25 constants, the stopword
  list, bigram weight, whitespace trimming, the RRF rank offset, a dropped
  scan row, an inclusive score floor) were all caught.
* **Reclamation mutant:** freeing snapshots immediately instead of through
  epoch reclamation is caught by `rag_stress` under ASan within seconds.

## Continuous integration

`.github/workflows/ci.yml` runs on every push and pull request. All test
jobs build with `-Werror`:

| Job | Covers |
|---|---|
| gcc-native | the runner's best ISA (AVX-512 when present), plus a demo and benchmark smoke run |

| clang-native | Clang 18 |
| gcc-asan-ubsan | AddressSanitizer + UndefinedBehaviorSanitizer |
| clang-asan-ubsan | the same with Clang, whose UBSan also checks arithmetic on null pointers |
| gcc-tsan | ThreadSanitizer: concurrency tests repeated 25 times, then `rag_stress` for 10 s per mode |
| fuzz-smoke | both fuzzers for 60 s each, seeded by `make_seeds`; crashing inputs uploaded as artifacts |
